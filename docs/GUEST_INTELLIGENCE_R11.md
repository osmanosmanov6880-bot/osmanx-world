# OSMANX Guest Intelligence R11 — управляемые пилоты и проверяемый экспорт

18 ноября 2026. База: R9 с диагностикой, R10 с production readiness. R11 не подключает Stripe, не принимает реальные платежи и не включает live API на VPS.

## Пять инженерно-продуктовых блоков

### 1. Неизменяемая история задач

Миграция 009_guest_action_history.sql добавляет tenant-scoped industry.guest_action_history. Поля: tenant_id, pilot_id, action_id, actor_id, event_type, старый и новый статус, ответственный, срок, версия действия, recorded_at. Unique tenant+action+version запрещает дубль события одной версии.

- FORCE ROW LEVEL SECURITY, runtime-роль только SELECT и INSERT; SQL trigger запрещает UPDATE/DELETE.
- Для существующих R9-задач создан только тип baseline, показывающий текущий снимок. Система НЕ выдумывает старую историю.
- Новые события: created, status, assignment; запись атомарна с изменением задачи и существующим audit/outbox.
- GET /api/industry/v1/guest/pilots/:id/actions/:actionId/history доступен только сотрудникам своего tenant, без контактов гостей.

### 2. Переназначение задач, версии и сроки

PATCH /api/industry/v1/guest/pilots/:id/actions/:actionId/assignment

Тело JSON:

    {
      "expectedVersion": 1,
      "assigneeId": "00000000-0000-4000-8000-000000000001",
      "dueDate": "2026-11-25"
    }

Только owner/manager. FOR UPDATE блокировка действия, ожидаемая версия, реальное изменение сотрудника или срока, срок от текущей даты до 180 дней, действующий сотрудник собственного tenant и роль не viewer. Запрещены повтор старой версии, чужая компания и переназначение закрытых/отклонённых действий. Оператор меняет только статус назначенного ему действия; каждый переход добавляет историю.

### 3. Операционная очередь владельца

GET /api/industry/v1/guest/operations — только владелец/управляющий.

Сигналы: просроченные задания, закончившееся окно возврата при незавершённом пилоте, отсутствие наблюдений после трёх дней работы, зависшая независимая проверка/доработка свыше семи дней. Риск сопровождается наблюдаемой причиной и следующей проверкой, но не обещанием прибыли. UI показывает ограниченную очередь; если записей больше лимита, truncated=true. Итоги относятся к просмотренному срезу, а не автоматически ко всей базе.

### 4. Двойная проверка доказательств и операционного пакета

GET /api/industry/v1/guest/pilots/:id/operations/export.json — только owner/manager.

Пакет включает frozen protocol, исходные агрегаты, оригинальный evidence SHA-256, решение проверяющего, задания, зарегистрированную хронологию и журнал импорта без сырого CSV. snapshot канонически сортируется и защищён отдельной SHA-256. При более 500 событиях или импортах пакет отклоняется вместо выдачи неполного отчёта.

Web Crypto в браузере пересчитывает SHA-256 snapshot и SHA-256 вложенного evidence перед сохранением. Никаких localStorage/sessionStorage, данных отдельных гостей или электронной подписи. SHA-256 — средство обнаружения изменений, а НЕ подтверждение издателя, оплаты или причинного роста.

### 5. Русский кабинет и сквозная приёмка

В R11 добавлены панель приоритетов, кнопка открытия пилота из очереди, просмотр истории, передача ответственному со сроком и проверяемый экспорт. Старые R9 workflow остаются.

Проверки: real PostgreSQL 16 с owner/manager/operator/viewer и чужой компанией; независимая история версий, конкурентные изменения 200/409, отказ SQL UPDATE, RLS, экспорт SHA, ограничение размера; детерминированные unit-тесты; Chromium desktop/mobile; двухключевое encrypted DR для evidence.v1 и evidence.v2 и новой истории; воспроизводимый release manifest с migration 009; HTTPS-публикация статики.

## Внедрение без ложных обещаний production

- PR объединяется только после зелёных PostgreSQL, Chromium, DR и release.
- Публичный HTML — не запущенная серверная база. У deploy-osmanx нет подтверждённых прав администратора на Docker/PostgreSQL/Nginx; обходить их запрещено.
- Применять миграцию 009 на настоящий сервер разрешено только с админ-доступом и проверенным offsite DR; не удалять новые таблицы при откате. Предыдущий образ может не знать новые API, но история сохраняется.
- GUEST_WRITES_ENABLED=false до независимого согласованного пилота; Stripe, VAT, рублёвые счета и подписки здесь не активируются.
- Инструкция для операторской read-only проверки: bash ops/r10-operator-gate.sh /private/staging.env /private/release.tar.gz

## Пользовательский сценарий

Владелец создаёт пилот и фиксирует протокол. Управляющий назначает задания. Руководитель видит просроченные задачи, передаёт исполнение конкретному сотруднику, не стирая прежний факт назначения. Второй сотрудник независимо рассматривает результаты. Владелец выгружает JSON-пакет с двумя SHA-256 и передаёт аудитору. Это помогает проверить управленческие гипотезы, но не доказывает рост прибыли, не подтверждает оплаты и не устанавливает автоматически причину потери гостей.
