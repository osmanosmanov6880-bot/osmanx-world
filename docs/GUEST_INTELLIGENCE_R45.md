# OSMANX Guest Intelligence R45 — 31 PR, актуальный main и независимая проверка перед ручным слиянием

**Дата:** 20 ноября 2026  
**Источник:** Draft PR R44 #90 (SHA `18bb8da6ba360a4a54fbd9b4bedb913fb23c1d1c`).  
**Статус:** только проверка исходников и подготовка к человеческому ревью; **production/customer NO-GO**.

## Пять реализованных инженерных направлений

1. **Настоящая проверка main против PR #47.** Обнаруженный R44 false-negative вызван необязательным полем `head_commit` у GitHub compare API. R45 отдельно выполняет `GET /git/commits/<pinned SHA>` и проверяет одновременную неизменность `main`, статус сравнения и числа ahead/behind. Если коммиты разошлись, отчёт требует ручного согласования, но не совершает GitHub-модификаций.

2. **Пробное разрешение Git-конфликтов без слияния.** В чистой одноразовой копии репозитория запускается `git merge-tree --write-tree --name-only --no-messages <fresh-main> <pinned-R14-SHA>`. Вывод — действительные конфликтующие пути и контрольный SHA временного дерева. Отчёт не содержит исходников, секретов, клиентских данных; `git merge-tree` создаёт только временные объекты в disposable Git базе, не создавая коммитов или обновлений веток.

3. **Проверка CI на точном HEAD всех 31 PR.** Для каждого SHA R14–R44 производится чтение GitHub Check Runs, сверка `head_sha`, проверка полноты одной страницы (при >100 записях срабатывает fail-closed), реальных статусных заключений GitHub Actions. Очередные, отменённые, проваленные, пропущенные и отсутствующие проверки не считаются зелёными. Старые проверки не засчитываются вместо проверок нового SHA.

4. **Объединённый независимый reviewer handoff.** Пакет объединяет полные 30 PR R44 и Draft PR #90, проверяет SHA истории, независимость и актуальность одобрений, фактический current-main, CI, защиту `main` (неизвестная/403 — блокер), список конфликтующих файлов и первый ручной барьер. Пакет содержит строгую ручную последовательность ревью/слияния, но не утверждает права делать merge.

5. **Трёхчастная GitHub Actions приёмка.** Отдельные задания на новые/предыдущие негативные тесты и npm lock, реальное `merge-tree` на временном runner и GET-only audit всех 31 PR с JSON+Markdown handoff. Каждая проверка безопасна для production и создаёт только временные CI-артефакты.

- `node services/industry-api/scripts/r45-live-release-audit.mjs --json /path/to/r45-merge-preview.json` с токеном GitHub, разрешающим только чтение PR, commits и checks.
- CI: `.github/workflows/guest-r45-acceptance.yml`

## Безопасный план ручного объединения

1. Независимый ревьюер анализирует **PR #47** против **нового main**, реальные конфликты и договаривается об изменениях. При необходимости новый *отдельно проверяемый* reconciliation-коммит создаёт человек, имеющий право на ветку. Не переписывать старые SHA без пере-проверки всей цепочки.
2. Ревьюер отдельно подтверждает каждый последующий текущий HEAD R15–R44, проверяет права и действующие правила branch protection, не учитывает одобрения к старым SHA.
3. Уполномоченный человек вручную сливает PR строго в порядке зависимостей, только если состояние ветки и CI актуальны.
4. После этого отдельно запускаются **новые** тесты на актуальном `main`, затем реальная staging-приёмка и независимое проверенное восстановление зашифрованной внешней копии.
5. До завершения юридической, privacy, эксплуатационной и двухличной приёмки оставить `GUEST_WRITES_ENABLED=false`, STOP-ограничения не снимать.

**Не путать:** зелёные исходные CI и отсутствие Git-конфликтов не гарантируют успешный текущий main CI, независимую приёмку, безопасность production и право работать с клиентскими данными.

**R45 не выполняет слияния, одобрения PR, отправку в production, миграции реальной БД, операции с личными данными или lifting STOP.**
