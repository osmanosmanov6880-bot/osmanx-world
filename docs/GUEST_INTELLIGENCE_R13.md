# OSMANX Guest Intelligence R13 — остановка пилота, качество данных и журнал безопасности

18 ноября 2026. Основа: опубликованный R12. Миграция: 011_guest_pilot_safety.sql.
**Этот релиз не включает реальный production Industry API на VPS.** GitHub может опубликовать только готовую статику; запуск PostgreSQL, Docker и Nginx требует отдельного разрешённого административного доступа. GUEST_WRITES_ENABLED=false — безопасное значение по умолчанию.

## Пять реализованных блоков

### 1. Защищённое состояние остановки и неизменяемый журнал

Миграция 011 создаёт две tenant-scoped таблицы:
- industry.guest_pilot_holds хранит текущую остановку выбранного пилота: active, reason_code, held_by/held_at, resolved_by/resolved_at, version; каждая запись привязана к pilot_id и tenant_id. Срок хранения событий не стирается при возобновлении.
- industry.guest_pilot_hold_events — неизменяемые события held/resumed, actor_id, reason_code, hold_version, recorded_at. Уникальная версия исключает дубли в истории.

Для обеих таблиц ENABLE + FORCE ROW LEVEL SECURITY и tenant policy. Runtime имеет SELECT/INSERT/UPDATE только для текущего состояния, SELECT/INSERT для событий. Триггер запрещает UPDATE/DELETE истории даже если администратор случайно использует прямой запрос.

Свободный текст, имена и контакты гостей не собираются: только четыре ограниченные причины: source_integrity, consent_review, data_quality, operational_incident.

### 2. Реальный экстренный стоп и независимое возобновление

- GET /api/industry/v1/guest/pilots/:id/safety — текущая остановка, качество агрегатов и версия.
- POST /api/industry/v1/guest/pilots/:id/safety/hold — owner, manager или operator может сразу остановить конкретный running пилот с expectedVersion и reasonCode.
- POST /api/industry/v1/guest/pilots/:id/safety/resume — только owner или manager, другой аккаунт, чем автор последней остановки, с expectedVersion и acknowledge=true. Прямой replay старой версии: HTTP 409.
- Каждая смена состояния атомарно обновляет pilot.version (инвалидация старых CSV-предпросмотров), записывает событие, audit_events и outbox в транзакции.

Проверка active hold встроена **в пять серверных маршрутов**: добавление агрегата, предпросмотр CSV, commit CSV, отзыв агрегата и submit результатов. Это не просто выключенные кнопки. После pause все эти операции возвращают HTTP 409 до независимого возобновления. При этом чтение истории, журналов и диагностики остаётся доступным для разбора.

Пауза не переписывает phase, protocol, observation evidence v1/v2, R12 approvals, оригинальные SHA-256, архивы и результаты независимого reviewer.

### 3. Операционный контроль качества без ложной причинности

Чистая функция assessGuestQuality(pilot, observations):
- NO_OBSERVATIONS — нет агрегатов;
- INVALID_COUNTS — числовая ошибка;
- DUPLICATE_DAY — дубли периода;
- OUT_OF_PROTOCOL — дата вне протокола;
- LATE_REGISTRATION — протокол зафиксирован задним числом;
- GROUP_IMBALANCE — размеры групп различаются более 1.5 раза;
- INSUFFICIENT_SAMPLE — расчётный минимум не достигнут;
- RATE_SWING — изменение доли возврата более 30 п.п. между соседними периодами;
- PERIOD_GAP — перерыв между периодами более семи дней;
- MANUAL_SOURCE — отдельная проверка ручного источника.

Предупреждения имеют наблюдаемый повод, приоритет и предлагаемую проверку. Они **не** означают доказанную ошибку, потерю прибыли или причинный эффект. Диагностика не отключает сбор автоматически; экстренная остановка — отдельное управленческое решение с идентифицируемым ответственным.

### 4. Проверяемый пакет безопасности и зашифрованный DR

GET /api/industry/v1/guest/pilots/:id/safety/export.json для owner/manager экспортирует:
- текущую активную остановку и источник решения;
- зарегистрированную историю событий held/resumed (максимум 100, пакет не обрезается молча);
- объективные предупреждения качества;
- оригинальный SHA-256 доказательств пилота, без изменения самих агрегатов;
- дополнительный SHA-256 snapshot пакета.

Браузер проверяет SHA-256 пакета через Web Crypto перед скачиванием. Контрольная сумма не является криптографической подписью издателя.

Тест зашифрованного восстановления двумя независимыми age identity проверяет прежние evidence v1/v2 и R12 approvals, а также новую историю held/resumed с собственным SHA-256, десятичными версиями и триггером неизменяемости после восстановления. Проверяется изолированная PostgreSQL БД, не существующий production VPS.

### 5. Интерфейс руководителя и полноценная CI-приёмка

Русский кабинет R13 показывает причину остановки, количество периодов, десять правил качества, кнопки остановки/возобновления, блокировку наблюдений/импорта/submit и проверяемый экспорт. Управляющий, совпадающий с автором остановки, не сможет возобновить её; независимая проверка проверяется также сервером.

Приёмка включает:
- unit тесты детерминированных предупреждений и целостности архива;
- реальный PostgreSQL с двумя организациями, owner/manager/operator/viewer, запрет прямых SQL UPDATE событий, cross-tenant RLS, версионную защиту и пять endpoint stop guards;
- Chromium desktop/mobile: работающая панель, браузерный стоп и отключение формы/CSV/submit, контроль SHA-256 перед скачиванием;
- миграцию 011, 11 таблиц FORCE RLS, least privilege runtime, воспроизводимый release manifest и публичный HTTPS-маркер R13;
- два независимых восстановления PostgreSQL из зашифрованных копий.

## Операторский GO/NO-GO и границы

Для первого настоящего клиента нужны: администратор production VPS, секреты вне репозитория, рабочий PostgreSQL API, проверенный offsite backup/restore реальных данных, согласованный протокол, полномочия и согласия на обработку данных, работающие учётные записи двух сотрудников, серверный R12 и операционный R13. Без этих условий только публичный статический UI и синтетический CI staging. Не запускать docker compose down -v и не считать зелёный GitHub CI разрешением на реальные клиентские записи.

Объяснение для бизнеса: когда появляется сомнение в источнике или законности измерений, сотрудник остановит сбор за одно действие. Возобновить его в одиночку не сможет, а все причины и решения остаются проверяемыми, не подменяя статистическое доказательство или договор.
