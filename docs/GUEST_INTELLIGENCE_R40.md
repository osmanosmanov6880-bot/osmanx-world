# OSMANX Guest Intelligence R40 — устранение обходов admission, AGE, Compose и PR patch

Дата: 20 ноября 2026. Базовый ревизионный HEAD R39: `e3e64642f679e4cc5bff56a98a96d4ee7d56221d`. Это отдельный stacked Draft поверх PR #76. Ни один операторский GO, merge, production deploy или снятие STOP не выполняется.

## Пять крупных полноценных блоков

### 1. Безопасные файлы операторского допуска R14
`src/guest-r40-secure-files.mjs` подключён к действительному `scripts/r14-admission.mjs`. Для фактических файлов используется открытый файловый дескриптор с `O_NOFOLLOW`, `fstat`, проверкой owner/private chmod, запретом hardlink и symlink по всем компонентам пути (`realpath` против канонического пути), исключением Git checkout, ограничением размера и количеством прочитанных байт. Нет прежнего разрыва `lstat(path)` → `readFile(path)`. Защита не заменяет доверие к самому операторскому хосту; произвольные rename-гонки с правами изменения родительских каталогов остаются вне гарантии Node.js.

### 2. Хронология подписанных R14 решений
`src/guest-r40-admission-timeline.mjs` интегрирован в `evaluateAdmission` и делает невозможным положительный отчёт по формально подписанному, но семантически неверному пакету. Проверяется канонический UTC timestamp (включая нормализацию невозможных дат), время каждого доказательства **не позже** принятия решения обоими независимыми подписантами, корректный срок действия и полный список семи подписываемых полей каждого одобрения без новых неподписанных `GO`-флагов. Оригинальная Ed25519-проверка R14 сохраняется.

### 3. Защищённый AGE snapshot и точная привязка SHA-256
`src/guest-r40-archive-integrity.mjs` и `scripts/r40-archive-check.mjs` подключены непосредственно в `ops/restore-dr.sh`. Перед дешифрованием архив и sidecar копируются в приватный одноразовый каталог **без перехода по симлинкам**. Затем проверяется точное имя `industry-YYYYMMDDTHHMMSSZ-N.dump.age`, **ровно одна** строка GNU sha256sum с этим именем, содержимое ciphertext через чтение открытого дескриптора, приватность AGE identity и пределы размера. Расшифровывается только проверенная локальная копия. Безопасность PostgreSQL R39 и `pg_restore --single-transaction` сохранены. SHA-256 подтверждает совпадение байт, но не независимую подлинность источника.

### 4. Реальная Compose boundary: только доверенный скрипт настройки ролей
`src/guest-r39-compose-boundaries.mjs` и `scripts/r38-check-compose.mjs` теперь связывают допустимый read-only bind `/ops/provision-roles.sh` с **точным абсолютным путём** текущего рабочего дерева. Ранее разрешалось любое `/attacker/ops/provision-roles.sh`. Запрещены непустые `extra_hosts`, в том числе объектные формы, нестандартные DNS/links, sysctls, привилегии и отсутствие `no-new-privileges:true` у любого сервиса. При ошибке R14 canary отказывает до `up`.

### 5. Полнота живых патчей GitHub PR #47
`src/guest-r40-patch-integrity.mjs` интегрирован в `src/guest-r39-review-packet.mjs`. Для каждого из точных десяти файлов анализируются все unified diff hunks: заявленные старые/новые длины против содержимого, сумма `+`/`-` против фактических GitHub additions/deletions, непрерывность hunks, отсутствие обрезанных и некорректных строк. Недостаточно, чтобы API просто прислал строку `patch`. Результат `allHunksVerified` входит в SHA-256 пакета. Скрипт остаётся read-only и не заменяет независимое человеческое ревью или анализ ветки после последующих merge.
