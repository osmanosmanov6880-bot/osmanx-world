# OSMANX Guest Intelligence R44 — полная цепочка ревью и контроль зависимостей

Дата: 20 ноября 2026. **Статус: отдельная Draft-ветка, NO-GO для реальных клиентов**.

## Пять инженерных блоков

1. **Все 30 PR R14–R43.** Дерево зависимостей зафиксировано на SHA источников от #47 до #84. `guest-r44-full-chain.mjs` проверяет текущее состояние каждой исходной ветки, точные base/head и полноту последовательности.
2. **Независимое ревью.** Не учитываются авторские, бот-ревью, устаревшие, отозванные одобрения и остающиеся `CHANGES_REQUESTED`. Первое ручное препятствие всегда конкретный PR с причинами отказа.
3. **Живой аудит GitHub без записи.** `node scripts/r44-review-full-chain.mjs --json` и `--markdown`. Используются только GitHub GET, контроль изменения main, сравнение первого PR, попытка чтения protection (403/404 = **не проверено**). Нет автоматического merge, rebase или развёртывания.
4. **Непротиворечивый npm-аудит.** Модуль `guest-r44-npm-audit.mjs` сверяет весь набор счётчиков severity, `total`, число и форму карточек уязвимостей. Ошибки/недостоверность данных и high/critical дают fail-closed; успешный отчёт — лишь снимок текущих сведений реестра.
5. **Отдельная GitHub Actions-приёмка.** Проверка Node 22, регрессии, зафиксированный R43 `package-lock.json`, два последовательных `npm ci` (второй **offline** из локального npm-кеша), актуальный npm audit и отдельная read-only проверка 30 PR с файлом доказательств.

## Приёмка

- `node --test test/guest-r44-acceptance.test.mjs`
- `node scripts/r43-supply-verify.mjs --lock`
- `npm ci --ignore-scripts --no-audit --no-fund` и повторный `npm ci --ignore-scripts --offline --no-audit --no-fund`
- `node scripts/r44-review-full-chain.mjs --markdown` (нужен `GITHUB_TOKEN` только с доступом на чтение репозитория и PR)
- `.github/workflows/guest-r44-acceptance.yml`

## Границы доказательств

Тридцать проверенных SHA не равны тридцати утверждённым человеком PR. GitHub Actions в PR не подменяет CI уже объединённого `main`. Проверка повторного `npm ci --offline` на одном runner не доказывает полностью изолированную air-gapped машину; базовый Docker-образ остаётся без независимо закреплённого digest и независимой подписи.

**Запрещено считать релиз разрешённым**, пока не пройдены фактическое независимое ревью и последовательный ручной merge, новый CI на актуальном main, защищённый staging, реальное внешнее восстановление, юридические разрешения и независимая подписанная provenance.

**Production, main, реальные записи гостей, STOP-флаги и данные клиентов не изменять.**
