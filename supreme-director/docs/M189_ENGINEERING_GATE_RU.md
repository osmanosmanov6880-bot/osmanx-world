# OSGARD SUPREME DIRECTOR · M189 — проверяемый допуск к интеграции

Дата: 4 ноября 2026 года. Контекст: PR #7, ветка `recovery/supreme-director-m187-20261104`.

## Реализовано

В `m189/admission.py` реализована самостоятельная **локальная проверка свидетельств** для 180 оригинальных инженерных заданий. Проверка работает только на чтение: не выполняет указанные в отчётах команды, не изменяет Git, не подключается к сетевым сервисам и не разрешает выпуск.

1. Проверяет SHA-256 оригинального `DIRECTOR_MASTER_180.md` и происхождение восстановленного плана.
2. Требует ровно шесть записей канонических исходников, жёстко закреплённые Git commit и tree SHA, корректный GitHub `origin` и локально воспроизводимый checkout.
3. Проверяет подпись Ed25519 владельца источника от точного набора полей `team/repo/commit/tree`; неизвестным ключам не доверяет.
4. Проверяет реальные байты файлов по SHA-256; отвергает небезопасные пути, выход за корневую папку и ссылки наружу.
5. Проверяет пять категорий тестовых доказательств: unit, integration, negative, regression, E2E. Любой ненулевой exit-code, отсутствующий журнал или неправильный хеш останавливает допуск конкретной задачи.
6. Проверяет наличие откатного артефакта и его хеша; требует отдельную подпись Ed25519 проверяющего для заявления о тестах.
7. Учитывает зависимости из исходного документа и не повышает статус, если родительские задачи ещё не предоставили проверяемые свидетельства.
8. Генерирует детальный JSON по 180 задачам с причинами блокировки. Историческая приёмка всегда остаётся **0/180**, и выпуск всегда **NO_GO**: локальные подписи сами по себе не доказывают независимую продуктовую приёмку.

**Важно:** проверки подписей и локального Git подтверждают целостность свидетельств относительно предоставленных доверенных ключей. Они *не доказывают* права на удалённый репозиторий, регистрацию публичного релиза или подлинность внешнего тестового окружения. Положительный результат отдельной заявки только `READY_FOR_EXTERNAL_REVIEW`.

## Команды

Из корня `osmanx-world`:

```bash
python3 supreme-director/m189/admission.py \
  --plan supreme-director/recovery/ORIGINAL_180_TASKS.json \
  --master supreme-director/originals/DIRECTOR_MASTER_180.md \
  --upstreams supreme-director/m189/data/M189_UPSTREAMS.json \
  --submissions supreme-director/m189/data/M189_SUBMISSIONS.json \
  --trust supreme-director/m189/data/M189_TRUST_KEYS.json \
  --workspace /path/to/read-only/team-checkouts \
  --evidence-root /path/to/verified-test-logs \
  --output /tmp/OSGARD_M189_ADMISSION_REPORT.json

python3 -m unittest discover -s supreme-director/m189/tests -p 'test_*.py' -v
```

`--require-production-ready` возвращает код 2 при `NO_GO`. **Не используйте эту программу как единственный механизм принятия релиза.** При отсутствии источников обычный отчёт возвращает статус `BLOCKED_UPSTREAM` для всех 180 задач — это ожидаемое проверяемое поведение, а не ошибка приложения.

## Принцип доверия

`M189_TRUST_KEYS.json` намеренно пуст: никто ещё не зарегистрирован независимым проверяющим. Публичные ключи можно добавить только после документированной верификации владельца через отдельное ревью. Приватные ключи и секреты нельзя коммитить. Смена доверенных ключей должна проходить отдельным аудитом; подпись и ключ из одного непроверенного PR не дают достаточной независимости.

`M189_UPSTREAMS.json` не заполняется именами предполагаемых репозиториев: созвучие названий не является доказательством ownership. До подтверждения канонических исходников шести команд состояние остаётся заблокированным.

## Отрицательные проверки

19 синтетических автотестов проверяют: неизвестные ключи, подделанные подписи, заменённые файлы, повреждённые журналы, дрейф Git HEAD, недопустимые схемы, зависимые задачи, дубликаты, traversal, symlink, отказавшие тесты и запрет ложного `VERIFIED`. Положительный синтетический тест подтверждает лишь способность распознать валидную **локальную** подпись и рабочее дерево. Никакая реальная интеграция внешних систем не запускается.

## Оставшиеся блокеры

- Оригинальные M180/M181 Git commits и архивы отсутствуют.
- Шесть источников пока не установлены как owner-approved canonical upstream.
- Полные end-to-end проверки на реальных продуктах и независимая приёмка отсутствуют.
- Платежи, отправки сообщений, управление устройствами и деплой не выполняются.

**Дальнейшая работа:** восстановить source-of-truth каждого реального продукта, оформить независимую верификацию ключей и только затем подключать соответствующий sandbox. Нельзя называть 19 синтетических тестов исполнением 180 продуктовых пакетов.
