# M192 — первая рабочая интеграция шести доменов (новый код)

**Дата:** 5 ноября 2026. **Ветка:** `recovery/supreme-director-m187-20261104`. **Production:** `NO-GO`.

После запроса владельца перестать искать отсутствующие M180/M181 разработан новый **исполняемый локальный runtime** на Python 3.11+ и SQLite, без сторонних зависимостей. Это не имитация страниц: `Director.execute()` выполняет реальные операции с транзакционным сохранением, разграничением доступа и unit/HTTP-тестами. Но это самостоятельная разработка **по требованиям плана**, а не автоматически восстановленные исходные продукты.

## Реализованная функциональность

| Направление | Работающий модуль | Соответствующие пункты исходного плана (частично) |
| --- | --- | --- |
| TITAN | Tenant identity по токену, роли owner/operator/viewer, запись задач, журнал изменений, идемпотентность | X06–X08 |
| NEXUS | Создание и чтение решений с альтернативами, выбором и обоснованием | X02, X06 |
| COMMERCE | Клиенты, сделки, этапы воронки; атомарные операции и фильтрация по арендатору | X06, X07 |
| EXPERIENCE | Транзакционные бронирования, запрет двойного бронирования, отмена, повтор запросов | X03–X05 |
| GENESIS | Сохранение JSON-сцен с проверкой позиций, версий и доступом к истории | X02, X03 |
| ORBITAL | Только **офлайн-симулятор**: TTL, уникальный nonce, transport ACK отдельно от execution ACK | X03, X06, X07 |

Отдельно: HTTP JSON API `POST /v1/execute`, `GET /healthz`. При запуске сервер ограничен `127.0.0.1`; роль и tenant нельзя указывать через тело запроса. Токены создаются только локальной административной CLI и хранятся в базе в виде хешей.

## Проверки

Локальный Python 3.13: **46/46 тестов PASS**. Включены 10 одновременных попыток бронирования: **1 успех, 9 конфликтов**. Сценарий `demo.py` создал задачи/клиента/сделку/бронь/решение/сцену и симулированную команду; tenant isolation и ACK подтверждены. Исходники сопровождаются SHA-256-манифестом, `verify_source.py` подтверждает точный состав.

Команды из корня репозитория:

```bash
cd supreme-director/m192
python3 verify_source.py
python3 -m unittest discover -s tests -p 'test_*.py' -v
python3 demo.py
python3 -m osgard_m192 --db ./local.sqlite provision --tenant Sandbox --actor owner
python3 -m osgard_m192 --db ./local.sqlite serve --port 8712
```

API требует заголовок `Authorization: Bearer <token>` и JSON-объект с полями `operation`, `payload`, `idempotency_key`. Для записей ключ должен быть уникальным и неизменным для одного запроса. Токен из вывода `provision` является секретом: не публиковать его в GitHub или переписке.

## Ограничения

- Работающая *референсная* реализация не подключена к первоначальным шести закрытым продуктам. Оригинальные задачи ещё **0/180 независимо приняты**, потому что критерии каждого пакета требуют конкретные интеграции с настоящими компонентами.
- SQLite — локальная среда, не PostgreSQL RLS; роли прикладные, не доказательство полноты корпоративной безопасности.
- Нет реального спутникового управления, платежей, отправки сообщений, внешнего AI, публичного деплоя или других опасных внешних действий.
- Нет автоматического переноса предыдущих производственных данных. `main` остаётся неизменной.
- Для production требуются TLS, аутентификация через проверенную систему идентичности, тесты восстановления на реальных данных, аудит безопасности и отдельное решение владельца.

**Стратегия:** развивать новый продукт функциональными блоками, даже если исходные M180/M181 недоступны. Не переименовывать частичную функциональность в «180 задач выполнены».
