# OSGARD SUPREME DIRECTOR — M193: рабочая CRM и интерфейс

Дата: 5 ноября 2026 года. Ветка: `recovery/supreme-director-m187-20261104`, [PR #7](https://github.com/osmanosmanov6880-bot/osmanx-world/pull/7).

## Что реализовано в коде

M193 использует уже созданное локальное ядро M192 и его SQLite-базу, а не заменяет его демонстрацией.

1. **Клиенты:** создание через существующий M192 API, поиск и просмотр, изменение имени и контакта, контроль версии, запрет доступа между организациями.
2. **Сделки:** создание через M192, изменение названия и суммы, последовательные переходы `new → qualified → proposal → won`; `lost` доступен до завершения. Обновление через `expected_version`, чтобы параллельные запросы не затирали друг друга.
3. **Активности:** звонки, письма, встречи, заметки; привязка к клиентам и сделкам; дата следующего контакта; завершение с проверкой версии.
4. **Показатели:** количество клиентов, сделок, открытых и просроченных активностей, суммы по этапам воронки; вычисляются запросами к SQLite. Фиктивных показателей нет.
5. **Авторизация:** владелец/оператор могут вносить изменения, наблюдатель только просматривать. Токен не записывается в localStorage и живёт только в памяти страницы.
6. **Интерфейс:** русскоязычная адаптивная панель `/studio/`. Сервер отдаёт HTML/CSS/JS/локализацию с того же localhost-адреса, принимает JSON API `/v1/execute`. Не подключаются CDN и внешние сервисы.

## Запуск (Python 3.11+)

Из каталога `supreme-director` в GitHub:

```bash
PYTHONPATH=m192:m193 python3 -m osgard_m193 init --db ./m193-local.sqlite --tenant "Моя компания" --actor owner
PYTHONPATH=m192:m193 python3 -m osgard_m193 serve --db ./m193-local.sqlite --port 8713
```

Откройте **http://127.0.0.1:8713/studio/** и введите созданный локальный токен. Не публикуйте токен в GitHub или переписке. Команда `init` откажется перезаписать уже существующий файл БД. При обновлении существующей базы M192 используйте только `serve`: он создаст новые CRM-таблицы без удаления исходных данных. Перед миграцией сделайте резервную копию.

## Границы и безопасность

- Сервер принимает соединения **только на loopback** и сверяет HTTP Host/Origin, не выдаёт CORS-разрешения.
- Токены выдаются локальной командой и хранятся в базе только как SHA-256; веб-API не выдаёт новых токенов.
- Записи ограничены `tenant_id`, каждый write идемпотентен и попадает в аудит. Разные версии одной записи не объединяются автоматически.
- **Нет** внешних API, реальных платежей, отправки сообщений, управления устройствами или production-публикации.
- SQLite и браузерная панель M193 — локальная реализация части требований, а не подтверждение выполнения первоначальных интеграций шести независимых продуктов.

## Связь с исходными 180 задачами

M193 содержит **новую рабочую реализацию** функциональности, соответствующей частям COMMERCE-X06 (модель клиентов и организаций), COMMERCE-X07 (CRM, сделки и задачи), TITAN (роли и аудит). Это не означает, что исходные задачи получили статус независимой продуктовой приёмки. Каноническая историческая приёмка остаётся **0/180**, выпуск **NO-GO**.

Следующий приоритет: тестирование интерфейса на настоящем браузере и телефоне, резервное копирование CRM-таблиц, централизованное управление пользователями и защищённая конфигурация для пилотного развёртывания.
