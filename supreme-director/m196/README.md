# OSGARD SUPREME DIRECTOR — M196 · Проекты и этапы

**Новый исполняемый модуль** поверх M192–M195. Это не ещё один отдельно стоящий прототип: `Director196(Director195)` использует ту же SQLite, ключи авторизации, сделки, клиентов, сотрудников, идемпотентность и историю работы.

## Что уже работает

- Создать проект только из существующей сделки конкретной организации; клиент определяется из сделки автоматически.
- Составить до 30 последовательных этапов, задать срок, открыть/завершить этап с проверкой предыдущих этапов.
- Связать реальную задачу сотрудника с проектом и этапом, проверить соответствие связанной CRM-активности тому же клиенту и сделке.
- Защитить ссылки и списки правами (owner, operator, viewer), tenant isolation и проверками версии. Менеджер другой компании не может получить чужие ссылки.
- Завершить этап **только после выполнения всех привязанных задач**. Завершить проект можно только после выполнения всех этапов.
- Посмотреть реальный прогресс по стадиям, привязанные задачи и локальную проверяемую историю событий. **История не имеет независимого внешнего якоря**, в отличие от внешней проверки M190.
- Использовать русскоязычную панель `/studio/`: новый раздел «Проекты» — проекты, этапы, связь задач и прогресс. Нет внешних отправок.
- Использовать тот же локальный HTTP API `/v1/execute` с Bearer-токеном и идемпотентными операциями.

## Быстрый запуск (из корня git-репозитория)

**Только локально**. Нужен Python 3.11+, библиотека SQLite из стандартной поставки Python. Модули M192, M193, M194, M195 и M196 находятся в отдельных каталогах; `PYTHONPATH` должен включать каждый из них.

Linux/macOS:

```bash
export PYTHONPATH="supreme-director/m192:supreme-director/m193:supreme-director/m194:supreme-director/m195:supreme-director/m196"
python3 -m osgard_m196 init --db ./osgard-local.sqlite --tenant "Моя компания"
# Сохраните одноразовый токен, НЕ коммитьте его.
python3 -m osgard_m196 serve --db ./osgard-local.sqlite --port 8716
```

Windows PowerShell:

```powershell
$env:PYTHONPATH = "supreme-director/m192;supreme-director/m193;supreme-director/m194;supreme-director/m195;supreme-director/m196"
py -m osgard_m196 init --db .\osgard-local.sqlite --tenant "Моя компания"
py -m osgard_m196 serve --db .\osgard-local.sqlite --port 8716
```

Затем откройте `http://127.0.0.1:8716/studio/` и вставьте выданный токен. `init` не перезаписывает существующий файл; `serve` открывает прежнюю базу, добавляя таблицы M196 **без удаления старых данных**. Делайте резервную копию перед обновлением.

Для локальной демонстрации без сохранения данных:

```bash
python3 supreme-director/m196/demo.py
```

## Проверка кода

```bash
python3 -m unittest discover -s supreme-director/m196/tests -p 'test_m196.py' -v
python3 supreme-director/m196/verify_source.py
node --check supreme-director/m196/osgard_m196/web/app.js
```

Опционально браузерный smoke: `python3 supreme-director/m196/tests/browser_smoke.py` с установленным `playwright` и Chromium. В ограниченной среде браузер может вернуть `ERR_BLOCKED_BY_ADMINISTRATOR`; такой запуск не считается успешным и не включён в обязательный CI.

## Ограничения

- Подтверждение задач/этапов основано только на данных локальной БД и не является независимой продуктовой приёмкой.
- Исходные 180 инженерных пакетов из документа 17 октября пока не прошли независимую приёмку: **0/180**.
- Реальная интеграция шести внешних продуктов, SSO, банковские транзакции, рассылки, физические спутниковые устройства и production deployment **не реализованы и не разрешены**.
- Токены нельзя хранить в Git, имена и идентификаторы тестовых компаний вымышлены. Проверка в Chromium на физическом устройстве ещё нужна.
- Клиентские данные и права владельца доступны только локальному процессу. Этот сервер **нельзя** открывать наружу без самостоятельной security-hardening/ревью.
