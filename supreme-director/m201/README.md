# OSGARD SUPREME DIRECTOR M201 — Центр финансовых рисков

**Четыре больших блока:** финансовые правила, журнал предупреждений, реальные задачи M195, русский локальный интерфейс и CI. Модуль наследует M200 и использует существующую SQLite M192–M200.

## 1. Пять финансовых правил

- CASH_GAP — модельный баланс стал отрицательным.
- BALANCE_FLOOR — модельный баланс ниже минимального резерва.
- OVERDUE_RECEIPTS — ожидаемые поступления просрочены сверх порога.
- UNSCHEDULED_COSTS — плановые расходы без срока превышают порог.
- OVER_BUDGET_PROJECTS — количество проектов с прогнозом сверх бюджета выше порога.

Владелец задаёт горизонт 1–18 месяцев, пороги в целых копейках, условный баланс, ожидаемую долю поступлений и возможный перерасход. **Реальный баланс банка неизвестен.** Без явно сохранённой политики сканирование запрещено.

Операции: commerce.alerts.policy.get, commerce.alerts.policy.set, commerce.alerts.preview (только расчёт), commerce.alerts.scan (ручное сохранение результатов).

## 2. Инциденты, дедупликация, события

Один активный эпизод на правило и организацию. Повторный скан с теми же показателями не создаёт второй инцидент. Если изменились данные, обновляется текущий эпизод. Когда риск исчез, его статус становится cleared; повторное появление создаёт новый номер эпизода.

Статусы: open → acknowledged, open/acknowledged → dismissed (с обязательной причиной), open/acknowledged/dismissed → cleared при сканировании после исчезновения условия. Снятие вручную не доказывает решение проблемы, пока метрика не нормализовалась.

Все действия сохраняются в append-only журнале с локальной SHA-256 цепочкой. У неё **нет внешнего независимого якоря**.

Операции: commerce.alerts.list, commerce.alerts.history, commerce.alerts.ack, commerce.alerts.dismiss.

## 3. Задачи сотрудникам

Владелец вручную выполняет commerce.alerts.task.create. В одной транзакции: создание team_work M195, первоначальный work_history, локальное уведомление M195, привязка к инциденту. Проверяются активный токен сотрудника, роль владельца, ожидаемая версия и отсутствие уже назначенной задачи.

Сотрудник-operator видит только своё назначение через commerce.alerts.mine (без сумм) и основную рабочую область /studio/. Финансовые политики, портфель и суммы ему не открываются.

## 4. Русский интерфейс и безопасность

Адрес: http://127.0.0.1:8721/risks/ . Настройки, предварительный расчёт, запуск сканирования, предупреждения, делегирование, история. Только loopback, same-origin, bearer-токен в памяти вкладки без localStorage, без внешних вызовов.

### Первый запуск из корня репозитория

    export PYTHONPATH="$(pwd)/supreme-director/m192:$(pwd)/supreme-director/m193:$(pwd)/supreme-director/m194:$(pwd)/supreme-director/m195:$(pwd)/supreme-director/m196:$(pwd)/supreme-director/m197:$(pwd)/supreme-director/m198:$(pwd)/supreme-director/m199:$(pwd)/supreme-director/m200:$(pwd)/supreme-director/m201"
    python3 -m osgard_m201 init --db ./director-local.sqlite --tenant "Моя компания"
    python3 -m osgard_m201 serve --db ./director-local.sqlite --port 8721

На Windows в PYTHONPATH используйте точку с запятой между путями. Токен владельца показывается один раз и не должен попадать в Git.

### Существующая база M200

1. Остановить предыдущий сервер.
2. Создать проверенный SQLite backup, учесть WAL.
3. Запустить M201 командой serve --db ./existing.sqlite; **не использовать init**.
4. Проверить прежние CRM-операции и новые политики. Изменения схемы добавочные.

### Запуск проверок

    python3 -m unittest discover -s supreme-director/m201/tests -p 'test_*.py' -v
    python3 supreme-director/m201/smoke.py
    node --check supreme-director/m201/osgard_m201/web/app.js

CI прогоняет регрессии M192–M201 на Python 3.11 и 3.13.
