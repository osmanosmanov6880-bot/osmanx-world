# M201 · Инженерный журнал: четыре блока реализации

Дата: 5 ноября 2026. Репозиторий: osmanosmanov6880-bot/osmanx-world, ветка recovery/supreme-director-m187-20261104, PR #7 (Draft).

### A. Движок порогов

risk_rules.py: пять правил на основании прогнозирования M200 и портфельных показателей M199. Пороговые значения валидируются с проверкой типов и диапазонов. bool, float, отрицательные пороги и неразрешённые параметры блокируются. Политика создаётся вручную с проверкой версии.

### B. Инциденты

runtime.py: четыре новые таблицы SQLite: финансовые политики, эпизоды предупреждений, состояние каждого правила и неизменяемые события. Строгая изоляция tenant, owner-only финансовое чтение, оптимистическое версионирование, транзакционная идемпотентность. Ручной scan не включает фоновые операции.

### C. Делегирование

commerce.alerts.task.create интегрирует реальную задачу M195: team_work, work_history, локальное уведомление, связь с инцидентом — единая транзакция. Сотруднику доступна только его собственная обезличенная карточка по риску и стандартное рабочее задание.

### D. UI, HTTP, тесты

Русская адаптивная панель /risks/, защищённый loopback HTTP, токен только в памяти, DOM через textContent. API тесты включают RBAC, межорганизационную изоляцию, XSS-небезопасные пути не используются, CSRF origin, повторные запросы, аутентификацию, состояние и историю.

### Граница доказательств

Гипотетическая денежная модель ≠ банковские средства. SHA-256 локального журнала ≠ независимое подписание. Прохождение CI ≠ тестирование на физическом телефоне. Изначальные 180 заданий: независимая приёмка 0/180. Production NO-GO.

### Откат

До обновления проверить резервную копию M200, включая WAL. При откате остановить сервис и восстановить проверенную базу на отдельный путь; не удалять новые таблицы вручную. Запуск старого процесса на активно изменяющейся базе M201 без backup опасен.
