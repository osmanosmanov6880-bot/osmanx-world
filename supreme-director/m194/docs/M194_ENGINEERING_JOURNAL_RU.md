# M194 — Журнал инженерной разработки

**Дата:** 2026-11-05. **Ветка:** `recovery/supreme-director-m187-20261104`. **PR:** #7 (черновик).

## Цель

После M193 перейти от карточек CRM к ежедневному исполнению: массовый перенос клиентов, безопасная выгрузка, очередь повторных контактов, управление сроками и реальные показатели воронки. Все данные хранятся локально; не выполнять внешних отправок и действий production.

## Реализовано

1. `osgard_m194/runtime.py` — семь новых операций, наследующих RBAC, tenant isolation, audit и idempotency M192/M193.
2. CSV с жёсткой схемой и пределом 200 строк: предварительная проверка, SHA-256, атомарная запись, защита от повторной обработки.
3. Экспорт клиентов доступен только владельцу; опасные префиксы формул нейтрализуются, сохраняется корректное CSV-экранирование.
4. Очередь активностей: сроки, просрочка, отсутствие сроков; перенос с `expected_version`; массовое завершение до 50 записей в одной транзакции.
5. Метрики: реальные суммы сделок и доля выигранных среди закрытых. Это не прогноз и не доказательство коммерческого эффекта.
6. `osgard_m194/server.py` — same-origin локальные статические ресурсы и исправленная подача `/studio/ru.json`.
7. `osgard_m194/web/` — русскоязычная панель «Операции» в существующем CRM Studio, загружающая данные из API.
8. Регрессионные и негативные тесты: разные организации, viewer/operator/owner, ошибочный CSV, неверные версии, повторные операции, конкуренция, подделка Host/Origin, HTTP локализации.

## Ограничения

- Работа идёт с локальными SQLite и синтетическими тестами, не с данными реального клиента.
- У API всё ещё нет общего hosted-сервера, SSO, горизонтального масштабирования и независимо проведённого security audit.
- Данные из примера не должны публиковаться или копироваться в реальные учётные системы.
- Из 180 исходных задач независимо приняты **0/180**; это не процент готовности созданных новых компонентов.
- В этой партии нет платежей, переписки через сторонние API или управления устройствами.
