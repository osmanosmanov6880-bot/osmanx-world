# OSGARD SUPREME DIRECTOR — M203: выполнение решений и проверка результата

Четыре больших инженерных блока, локальное приложение поверх M192–M202, на той же SQLite. Настоящие риски M201, задачи M195, снимки M202, результаты M203. Это не банковская сверка и не доказательство причинно-следственной связи.

## 1. Планы действий, связанные с риском

Операции commerce.actions.create/start/cancel/list/get/history.
План привязывается к существующему активному предупреждению, к реальному исходному снимку с той же версией финансовой политики и конкретной числовой цели. Фиксируются гипотеза, срок, направление изменения. Только один открытый план на эпизод предупреждения. Доступные статусы: draft, active, model_reviewed, cancelled; optimistic version, идемпотентность и tenant isolation.

CASH_GAP, OVERDUE_RECEIPTS, UNSCHEDULED_COSTS, OVER_BUDGET_PROJECTS должны уменьшаться. BALANCE_FLOOR — увеличиваться. Для активации нужно назначить хотя бы одно поручение. Отмена плана не отменяет задачи сотрудников автоматически: возвращает их список для отдельной обработки.

## 2. Реальные задачи и ответственность

commerce.actions.step.add — атомарно создаёт настоящую строку team_work M195, запись work_history, локальное уведомление team_notices и финансовый шаг. Назначение только действующему сотруднику той же организации; не более 30 задач на план. Исполнитель завершает задачу через существующую titan.work.status M195. Сотрудник-operator видит только свои поручения через commerce.actions.mine, без суммы, цели и финансовой гипотезы. Владелец имеет полный доступ; viewer не допускается.

## 3. Оценка по наблюдениям до и после

commerce.actions.evaluate требует более поздний снимок M202, ту же версию политики M201, проверяемую hash-chain, выполнение задач M195 и сравнивает значение только того же финансового правила. Вывод может быть:
- TARGET_NOT_REACHED — цель не достигнута;
- TASKS_NOT_FINISHED — метрика улучшилась, но задачи не завершены;
- MODEL_TARGET_REACHED_REVIEW_REQUIRED — модельный критерий достигнут, нужен разбор владельца.

commerce.actions.review требует отдельного решения owner и письменного основания. Принятие возможно только если цель и порог риска достигнуты, все поручения закрыты, текущая версия плана совпадает и нет более нового снимка. Итоговый статус model_reviewed означает ТОЛЬКО, что владелец принял модельное наблюдение, а не реальную прибыль или установленную причинность. Отказ возвращает план к работе. Оценки и рецензии неизменяемы, журнал плана — локальная SHA-256 цепочка без независимой подписи.

## 4. Панель руководителя, CSV и CI

Локальная русская панель http://127.0.0.1:8723/actions/ : создание плана, поручения, выбор снимка, проверка результатов и отчёт. Запросы commerce.actions.report/report.csv делают сводку на основании реальных записей SQLite. CSV UTF-8 с BOM, escaping spreadsheet formulas. Интерфейс тёмный OBSIDIAN, адаптивен для телефонов; физическая визуальная приёмка ещё не выполнена.

Только loopback HTTP, same-origin CSP, токен только в памяти вкладки, нет сторонних запросов, реальных переводов или внешних уведомлений.

### Запуск

Из корня GitHub-репозитория Python 3.11+:

    export PYTHONPATH="$(pwd)/supreme-director/m192:$(pwd)/supreme-director/m193:$(pwd)/supreme-director/m194:$(pwd)/supreme-director/m195:$(pwd)/supreme-director/m196:$(pwd)/supreme-director/m197:$(pwd)/supreme-director/m198:$(pwd)/supreme-director/m199:$(pwd)/supreme-director/m200:$(pwd)/supreme-director/m201:$(pwd)/supreme-director/m202:$(pwd)/supreme-director/m203"
    python3 -m osgard_m203 init --db ./director-local.sqlite --tenant "Моя компания"
    python3 -m osgard_m203 serve --db ./director-local.sqlite --port 8723

Для существующей SQLite M202 НЕ запускайте init. Остановите старый сервер, создайте проверенный backup с WAL, запустите serve --db ./existing.sqlite. M203 только добавляет таблицы.

Команда M202 run-due сохранена в M203:

    python3 -m osgard_m203 run-due --db ./existing.sqlite --token-stdin

Токен администратора передаётся только по stdin из защищённого источника, не в аргументах команды. Системный планировщик подключается вручную.

### Методологические и релизные ограничения

Модель cashflow M200 содержит ручной сценарный начальный баланс. Сравнение показателей без контрольной группы, банковских данных и независимой верификации не доказывает пользу конкретного действия. При смене финансовой политики M201 сравнение блокируется. Для BALANCE_FLOOR минимум M200 включает исходный баланс: если он задан ниже резерва, одни будущие ожидаемые поступления не могут исправить этот минимум в том же сценарии.

Первоначальные 180 upstream-пакетов имеют 0/180 независимых приёмок. Production NO-GO. Основная ветка и production не изменяются. Визуальная проверка на реальных телефонах обязательна отдельно.
