# OSGARD SUPREME DIRECTOR — M197 · Карточка проекта

**Выполняемый код поверх M192–M196.** Локальное приложение с русским интерфейсом, tenant isolation, контролем прав и транзакциями SQLite. **Это не публичный SaaS и не независимая приёмка 180 исходных инженерных пакетов.**

## Работает

- Карточка существующего проекта из CRM с реальными этапами, прогрессом и привязанными задачами.
- Хранение документов `text/plain`, `text/markdown`, небольших `application/pdf` до 48 КиБ. Содержание сохраняется в локальной SQLite; каждая новая версия неизменяема и защищена SHA-256. Без автозагрузки в облако.
- Обязательства перед клиентом: срок, привязка к этапу, статус `open → fulfilled/waived`. Для исполнения требуется **хеш реально сохранённой версии документа данного проекта**. Снятие обязательства — только владелец с причиной.
- Запрет закрывать этап с открытыми обязательствами этого этапа и проект с любым открытым обязательством. Дополнительно установлены SQL-триггеры против обхода из более старого клиента M196.
- Сводка отклонений: просроченные этапы/обязательства, документы, открытые договорённости. Все метрики вычисляются из SQLite, без симуляции.
- Журнал изменений дополняет цепочку проекта M196; её SHA-256 **не заменяет независимое подписанное свидетельство**.
- Русская адаптивная панель по адресу `/projects/`. Существующий интерфейс CRM M196 остаётся по `/studio/`.

## Локальный запуск

Нужны Python 3.11+, SQLite. Из корня репозитория:

```bash
export PYTHONPATH="supreme-director/m192:supreme-director/m193:supreme-director/m194:supreme-director/m195:supreme-director/m196:supreme-director/m197"
python3 -m osgard_m197 init --db ./osgard-private.sqlite --tenant "Моя компания"
# Сохраните показанный одноразовый токен в безопасном месте.
python3 -m osgard_m197 serve --db ./osgard-private.sqlite --port 8717
```

На Windows PowerShell разделяйте значения `$env:PYTHONPATH` через `;`. После запуска откройте `http://127.0.0.1:8717/projects/`.

### Обновление существующей базы M196

1. Остановить старый сервер.
2. Сделать офлайн резервную копию SQLite **включая WAL**, проверить возможность восстановления.
3. Запустить `python3 -m osgard_m197 serve --db ./existing.sqlite` — `initialize` добавляет таблицы M197 без удаления прежних данных.
4. Проверить карточки проектов и доступы. Не запускать M196 и M197 одновременно на одной рабочей базе при критичных изменениях.

Откат — остановить M197, восстановить **проверенную резервную копию** перед миграцией и запустить M196. Старый M196 не понимает обязательств M197; ручное удаление таблиц или слепое переключение версии опасно.

## Тестирование

```bash
python3 -m unittest discover -s supreme-director/m197/tests -p 'test_*.py' -v
python3 supreme-director/m197/verify_source.py
node --check supreme-director/m197/osgard_m197/web/app.js
```

Запуск из корня git требует `PYTHONPATH` шести версий, как выше. Сквозной тест на локальном HTTP в `tests/test_m197.py` не отправляет внешних запросов. Опциональный `tests/browser_smoke.py` требует Playwright/Chromium; текущая среда блокирует loopback в Chromium сообщением `ERR_BLOCKED_BY_ADMINISTRATOR`, поэтому визуальная браузерная приёмка **не заявляется**.

## Ограничения

- Сервер доступен только по loopback, bearer-токен не сохраняется в браузере; реальный интернет/внешняя авторизация/платежи/рассылки не подключены. Публично развёртывать нельзя без отдельного аудита безопасности.
- PDF здесь **хранится как файл**, но не проверяется на вредоносное содержимое. Пользователь скачивает его локально, автоматическая обработка не выполняется.
- SHA файла доказывает совпадение байтов, но не подписание/согласие клиента. Статус `fulfilled` означает внутреннюю запись, не юридическую приёмку.
- Существующее API ограничивает HTTP-тело 128 КиБ; лимит документа M197 — 48 КиБ. Большие файлы требуют отдельной защищённой объектной подсистемы.
- Оригинальные 180 инженерных задач: **0/180 независимо приняты**; production — **NO-GO**.
