# OSGARD SUPREME DIRECTOR M195

Дополнение к M194: задачи сотрудников, ответственные, внутренние уведомления, сроки и история изменений. **Локальная система, не production.** Из исходных 180 задач 0 прошли независимую продуктовую приёмку.

## Запуск

Из родительской папки, содержащей каталоги `m192`, `m193`, `m194`, `m195`:

```bash
export PYTHONPATH="$PWD/m192:$PWD/m193:$PWD/m194:$PWD/m195"
python -m osgard_m195 init --db ./director195.sqlite --tenant "Компания" --actor owner
python -m osgard_m195 serve --db ./director195.sqlite --port 8715
```

Откройте `http://127.0.0.1:8715/studio/` и введите токен владельца. Токен выводится **только при локальном создании**; храните его вне репозитория. Новые токены сотрудникам выпускаются через локальный вызов метода `issue_token(...)` владельцем — публичного HTTP-метода выпуска токенов нет. Панель и API используют одно происхождение, CSP запрещает внешние скрипты и соединения.

## API

Все запросы `POST /v1/execute` с Bearer-токеном и телом `{"operation":"...","payload":{},"idempotency_key":null}`; для записей требуется уникальный ключ (8–100 допустимых символов).

| Операция | Доступ | Назначение |
|---|---|---|
| `titan.team.members.list` | владелец, оператор | активные сотрудники, без токенов |
| `titan.work.create` | владелец, оператор | новая задача, связь с CRM activity по желанию |
| `titan.work.list`, `titan.work.get` | по роли | записи в пределах организации |
| `titan.work.assign` | владелец | назначение действующему сотруднику |
| `titan.work.status` | владелец, исполнитель | перевод статуса с проверкой версии |
| `titan.work.note` | владелец, исполнитель | дополнение истории |
| `titan.work.history` | владелец, исполнитель, создатель-оператор | проверяемая локальная история |
| `titan.work.sla` | по роли | сводка просрочек и ближайших сроков |
| `titan.notifications.list` | по роли | личные внутренние уведомления |
| `titan.notifications.ack`, `titan.notifications.refresh` | владелец, оператор | прочтение и обновление напоминаний |

**Безопасность:** все операции защищены арендатором и авторизованным токеном; операторы не назначают задачи другим, а viewer не меняет данные. Транзакции `BEGIN IMMEDIATE` исключают двойную запись при конкурентных запросах. История связана SHA-256 и защищена SQL-триггерами от обычного UPDATE/DELETE. Она **не** заменяет внешний якорь/подписанный независимый аудит — администратор файла SQLite может изменить всю базу и пересчитать хеши.

**Уведомления:** только в SQLite; никакого Telegram, email, push, SMS и внешних отправок. Сканирование сроков запускается вручную при открытии раздела, фонового планировщика нет.
