# OSGARD SUPREME DIRECTOR M199 — инженерный журнал

Дата: 2026-11-05. Ветка: `recovery/supreme-director-m187-20261104`. PR #7. `main` без изменений.

## Цель

Поверх локального исполняемого M198 создать сводную аналитику бюджета и поступлений всех доступных проектов, без внешней сети и без новых платежных интеграций.

## Реализовано

1. `Director199(Director198)` — три read-only операции на существующей аутентификации, SQLite и tenant boundary.
2. Owner видит все проекты своего tenant; оператор — только `created_by=actor`, viewer отказано. Запросы к расходам и ожиданиям повторно фильтруются по `tenant_id` и `project_id`.
3. Сводные бюджет/факт/план/прогноз/ожидаемые поступления/риск, количество неполных бюджетов. Бюджет `NULL` не трактуется как бюджет 0.
4. UTC календарь: ожидаемые pending по сроку, manual recorded по `resolved_at`, incurred cost по `updated_at`; просрочки, без даты, до и после горизонта отдельно. Проверяется равенство контрольных сумм внутри отчёта.
5. CSV UTF-8 с защитой строк от интерпретации формул.
6. Локальный HTTP интерфейс `/portfolio/` и адаптивная русскоязычная панель. CSP, Host, Origin и same-origin ограничения наследуются от M192–M198.
7. Данные не создаются для отчётов и не копируются во внешние сервисы. Новых SQLite-таблиц нет.

## Обязательные проверки

- Автотесты `tests/test_m199.py` и `tests/test_http.py`: изоляция тенантов, RBAC, rollup, временные границы, прогноз, ручные записи, CSV, HTTP, негативные сценарии.
- `smoke.py`: создание реального синтетического проекта, бюджет, расход, ожидаемая оплата → отчёт, календарь, CSV.
- Проверка SHA-256 файлов по `M199_SOURCE_MANIFEST.json`.
- Регрессионные тесты M192–M198 без изменения исходных файлов.
- `node --check` для браузерного JavaScript.

## Известные ограничения

- Нет учёта даты планируемого фактического **списания** расходов в M198; поэтому достоверный денежный cash-flow на дату не заявляется. Категория `planned` входит в прогноз затрат, но не размещается на календарной оси расходов.
- Подтверждение `recorded` — локальная отметка с документом; банк не опрашивается.
- Полный финансовый и визуальный независимый аудит, нагрузочное тестирование при 1000 проектах и физический телефон ещё необходимы для production.
- Исходная историческая кампания на 180 пакетов не объявляется выполненной: `0/180`, production `NO_GO`.

## Откат

Остановить сервер M199 и запустить M198 на прежнем файле БД; M199 не меняет схему и не добавляет записи отчётов. Перед изменением окружения сделать проверяемую резервную копию БД и сохранить текущий Git SHA.

## Фиксация публикации

Точные SHA коммитов и GitHub Actions указывать только после завершения CI по опубликованному коммиту; локальный PASS не заменяет GitHub PASS.
