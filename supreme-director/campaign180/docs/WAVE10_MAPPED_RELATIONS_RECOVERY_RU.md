## 1. Перенос действующих связей с точной картой ID

`LocalMappedReferenceMigration` реализует:
- `mapping_options` — ограниченный список исходных связанных ID и
  целевых ID, предназначенный **только** для ручного выбора владельцем;
- `inspect` — проверка всех записей модели и фактических индексов
  `builder_links`, валидности исходных и целевых записей, контроля версий
  и схем, а также полного покрытия старых ID явной картой;
- `apply` — **только после подтверждения точного SHA-256 плана**.
  Выполняет в одной SQLite-транзакции перенос значений ссылок, 
  `target_model/target_row_id` в индексах, увеличение версий,
  пересчёт хешей, новую ревизию модели и immutable receipt.

Ограничения: до **500 записей**; все уникальные исходные ID должны
быть перечислены, лишние пары и дубликаты запрещены. Один новый ID нельзя
выбрать одновременно для двух разных исходных ID. Межпроектные и
межорганизационные связи невозможны. Испорченный индекс, зависимый
workflow, устаревшая версия или изменение хотя бы одной записи между
`inspect` и `apply` отменяют всю операцию. В API отсутствует
автоматическое «сопоставление по названию». Даже при наличии логики
миграций это не означает независимой security-приёмки.

## 2. Локальный пакет восстановления проекта

`LocalProjectRecovery` добавляет три операции с чётким разграничением:

1. `inspect`: только владелец получает **метаданные**
   (количество записей/связей, хеш архива, `PRAGMA quick_check`).
   Сами записи через HTTP не возвращаются.
2. `export_bytes` и `verify_bytes`: доверенная Python-библиотека
   создаёт канонический ограниченный JSON-архив со схемой, записями
   (включая удалённые), индексами связей и хешами. Проверяется вся
   схема, значения, уникальность UUID, порядок и соответствие
   `builder_links` действующим связям, размер не более **3 MiB**.
3. `restore_to_new_project`: создаёт **новый** изолированный проект
   с новым UUID в той же организации, атомарно восстанавливает записи
   и связи и выдаёт права **только исходному доверенному владельцу**.
   Исходный проект не изменяется, существующий проект перезаписать
   невозможно.

**Важно:** архив содержит реальные бизнес-данные, потенциально
персональные. Его необходимо хранить в шифрованном защищённом хранилище.
SHA-256 обнаруживает изменение содержимого, но не удостоверяет личность
создателя. Workflows, делегированные права пользователей, вебхуки,
секреты и история idempotency в архив не включены; полноценную
продуктовую disaster-recovery-процедуру это пока не заменяет.
Реальный экспорт доступен **только** доверенному локальному Python-коду,
а не браузерной кнопке или публичному URL.

## 3. Local API и визуальная консоль

- `POST /api/v1/references/map/options`
- `POST /api/v1/references/map/inspect`
- `POST /api/v1/references/map/apply`
- `GET /api/v1/recovery/inspect`

Сервер задаёт tenant/project/actor сам, клиент не может подставить их
в тело запроса. Публичного доступа нет — loopback `127.0.0.1` и
bearer-токен. В русской консоли для каждого старого ID показано
выпадающее меню новой записи, затем SHA-256-план и отдельное
подтверждение. Если исходных или целевых вариантов более 100,
браузерный мастер отказывается выполнять перенос и требует
проверяемого локального сценария.

## 4. Проверки и воспроизведение

`test_wave10_mapped_recovery.py` проверяет корректность фактических
SQLite-связей до и после переноса, устаревшие планы, испорченные
контрольные суммы, отсутствие лишних соответствий, невозможность
доступа другого проекта или роли, восстановление в новый проект,
нетронутый источник, защиту от перезаписи и отказ подменённым архивам.

`browser-console.mjs` расширен пользовательским сценарием
ручного выбора переноса в другую модель и вызова owner-only
проверки восстановления. Тест также сохраняет отдельные скриншоты.

```bash
export PYTHONPATH="$PWD/supreme-director/campaign180"
python -m unittest discover -s supreme-director/campaign180/tests -p 'test_*.py' -v
node --check supreme-director/campaign180/assets/console.js
node --check supreme-director/campaign180/tests/browser-console.mjs
node supreme-director/campaign180/tests/browser-console.mjs
```

Инструкция описывает **запланированные проверки**: их успешность
должна подтверждаться конкретным GitHub Actions run. На момент
публикации Wave 10 runner ещё не завершил CI. Подлинное интеграционное
подтверждение всех шести канонических продуктов отсутствует.
