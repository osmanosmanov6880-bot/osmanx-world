# OSGARD SUPREME DIRECTOR — Wave 9

Дата: 6 ноября 2026 года. Изменения только в рабочей ветке
`recovery/supreme-director-m187-20261104` / Draft PR #7.

## 1. Миграция полей-связей без потери данных

`LocalModelEditor.rename_reference_field` атомарно обновляет:

- системное имя поля в спецификации модели;
- JSON-ключи активных и удалённых записей (до 500 строк на проход);
- SQLite `builder_links.field` для всех фактических активных связей;
- порядок выбранных полей в секциях типа `form`;
- ревизию каждой переписанной записи, SHA-256 и историю проекта;
- локальную запись операции `RENAME_REFERENCE_FIELD`.

Перед изменением проверяется совпадение ссылочного индекса и JSON, а
также отсутствие зависимых workflow-условий и действий. На повреждённых,
неожиданных, чужих или устаревших связях вся транзакция откатывается.
Целевая модель каждой связи при переименовании **не меняется**.

`retarget_unused_reference` разрешает смену целевой модели только если
**ни в активных, ни в удалённых записях** нет значений этого поля,
а в `builder_links` нет его индексированных рёбер. Смена живой связи
без явного подтверждённого отображения идентификаторов запрещена.
Объём ограничен 500 строками.

## 2. Восстановление старой версии страниц

`LocalRevisionRestorer.inspect` возвращает SHA-256 план восстановления,
включая точные номера исходной и текущей ревизий, изменённые страницы и
информацию о совместимости. Если структура `models` отличается хотя
бы одним полем, восстановление **блокируется**: нельзя молча изменить
структуру сохранённых пользовательских данных.

`LocalRevisionRestorer.restore` требует явного подтверждения хеша плана.
Проверка плана, прав, старой ревизии и запись новой ревизии выполняются
в единой SQLite транзакции. История не переписывается, бизнес-записи,
таблицы отношений и workflows **не изменяются**. Для операции создаётся
отдельная immutable SQLite запись `builder_page_restores`.

## 3. Локальный API и русский интерфейс

- `POST /api/v1/schema/models/{model}/rename-reference`
- `POST /api/v1/schema/models/{model}/retarget-unused-reference`
- `GET /api/v1/revisions`
- `POST /api/v1/revisions/restore/inspect`
- `POST /api/v1/revisions/restore`

Организация, проект и пользователь задаются сервером, не телом HTTP.
Консоль содержит две явные формы миграции связей с подтверждением и
раздел «Версии и откат» с обязательным inspect → подтверждение SHA →
новая ревизия. Запросы продолжают обслуживаться только на
`127.0.0.1` по локальному токену.

## 4. Регрессия и браузерная приёмка

`tests/test_wave9_reference_restore.py`:
целостность живых, пустых и удалённых ссылок; cross-tenant и RBAC;
ограничение миграций; конфликт схем; неизменяемость истории; неверный SHA;
атомарный откат; сохранность записей и безопасность HTTP.

`tests/browser-console.mjs`:
реальное редактирование связей, пустое переназначение целевой модели,
временное изменение страницы и подтверждённое восстановление без
изменения клиентских записей, плюс мобильная проверка в Chromium.
**Наличие тестового кода не означает успешного CI.**

## Воспроизведение (локально)

```bash
export PYTHONPATH="$PWD/supreme-director/campaign180"
python -m unittest discover -s supreme-director/campaign180/tests -p 'test_*.py' -v
node --check supreme-director/campaign180/assets/console.js
node --check supreme-director/campaign180/tests/browser-console.mjs
node supreme-director/campaign180/tests/browser-console.mjs
```

Тест Chromium требует Node 22+, установленного браузера и временного
локального WSGI-сервера. Screenshot artifacts сохраняются в CI на 7 дней.

### Ограничения и критерий выпуска

Нет интеграции с каноническими шестью исходными upstream, независимой
security-проверки, подтверждённого production-деплоя, внешнего IdP и
публичной обработки форм. Любая массовая миграция реальных существующих
связей требует отдельного плана преобразования идентификаторов.
**Независимо принято: 0/180; release gate: NO-GO.**
