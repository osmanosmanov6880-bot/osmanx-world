# OSGARD — Wave 28: действия по реальным рискам (локальная версия)

## Пять реализованных блоков

1. **Риск → поручение**. Руководитель вручную выбирает актуальный сигнал Wave 26, привязывает действие к фактическому SHA-256-снимку задач, задаёт план, срок и действующего сотрудника. Уже исчезнувший риск и устаревший снимок отвергаются; одной паре риск/задача соответствует одно поручение.
2. **Контроль исполнения**. Поручение проходит состояния «открыто», «в работе», «решено». Закрытие требует явного комментария руководителя, не меняет исходную задачу и не заявляет, будто причина реально устранена. Повторное открытие возможно только при существующем риске.
3. **SQLite и контроль версий**. Изменения используют BEGIN IMMEDIATE, optimistic CAS, проверку ролей, ограниченные поля/размеры, idempotency key и запрет записи после отката основного сценария. Исторические карточки доступны для чтения.
4. **Проверяемый журнал и CSV**. На каждом обновлении записывается полная версия в неизменяемый триггерами SQL-журнал с цепочкой SHA-256; чтение сравнивает журнал и актуальную запись. CSV получает безопасные ячейки и контрольную SHA-256.
5. **Русский адаптивный интерфейс, API и регрессия**. Настоящие HTTP-маршруты GET/POST/PATCH, управление поручениями внутри монитора, статусы и выгрузка CSV, тесты в Python/Chromium с мобильным экраном.

## Границы

Локальный WSGI на 127.0.0.1; роли задаются доверенным локальным запуском, не регистрацией в Интернете. Уязвимости авторизации публичного SaaS здесь не решены. Ни автоматической отправки сообщений, ни реального SLA, ни автоматической оценки эффективности действия нет. SHA-256 доказывает согласованность сохранённых записей, **не является цифровой подписью** от внешнего атакующего. Это не независимая приёмка исходного плана: исходные 180 задач по-прежнему имеют 0/180 независимых подтверждений.
