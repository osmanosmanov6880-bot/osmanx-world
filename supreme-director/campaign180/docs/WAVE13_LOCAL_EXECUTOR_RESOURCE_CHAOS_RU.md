# OSGARD SUPREME DIRECTOR — Wave 13

Дата: 8 ноября 2026. Только `recovery/supreme-director-m187-20261104`, Draft PR #7. `main` и production не изменены.

## Пять полноценных локальных блоков

### 1. TITAN-X09 — исполнитель фиксированных операций

`sandbox_runtime.py` запускает отдельный subprocess `python -I -S -B` с абсолютным путём к доверенному `bounded_worker.py`. Разрешены четыре явно описанных вида локальных вычислений: сумма безопасных целых чисел (`sum_i64` только в точном JSON-диапазоне), SHA-256 строки, размер UTF-8 строки и синтетическая задержка для тестирования. Пользователь **не может** передать Python-код, shell-команду, путь, URL, import или сетевую инструкцию.

`TaskEnvelope` повторно проверяется по tenant/actor/scopes/capability/TTL и SHA-256. Ограничения: это **не** Docker/seccomp/VM/сетевой namespace; нет произвольного исполнения и нет интеграции в исходный DevSwarm. X09 имеет связанный локальный код, но полностью не принят.

### 2. TITAN-X10 — фактические POSIX RLIMIT

`resource_limits.py` проверяет допустимые бюджеты и устанавливает в дочернем процессе Linux/POSIX ограничение CPU (`RLIMIT_CPU`), виртуальной памяти (`RLIMIT_AS`), файловых дескрипторов (`RLIMIT_NOFILE`), core dumps (`RLIMIT_CORE=0`) и записи файла (`RLIMIT_FSIZE=0`). Родитель устанавливает независимый wall-clock timeout, завершает группу процесса при зависании, ограничивает размер входа и выхода. Ошибки настройки ресурсов запрещают запуск.

Диск и сеть не доступны через фиксированные операции; изоляция сети на уровне ядра **не реализована**, поэтому нельзя называть это полноценным sandbox ОС.

### 3. TITAN-X15/X10 — атомарный бюджет и одноразовые разрешения

`quota_ledger.py` вводит SQLite `BEGIN IMMEDIATE` для квот организаций, резервирования единиц вычисления, одноразового 256-bit токена, номера поколения, TTL, защиты от replay, commit/cancel и reclaim. Чужая организация не может списать единицы текущего tenant. Повтор одного idempotency-ключа не создаёт новый lease. `budgeted_runtime.py` связывает предварительную авторизацию, резерв и фактический subprocess; ошибка вычисления возвращает зарезервированную квоту.

Ограничение: квота **локальная на одной SQLite БД**, а не распределённый многоузловой бюджет и не биллинг.

### 4. TITAN-X29 — негативное и хаос-тестирование

`test_wave13_worker_quota.py`: 15 тестов реальных subprocess, доступа к недопустимым операциям, перегрузки входа/памяти, целочисленной точности, убийства по времени, неправильных tenant/scope, конкурентных резервов, forged token, повторного commit/cancel и восстановления TTL.

`sandbox_resilience.py` отдельно проверяет реальные операции, запрет shell, переполнение, timeouts, конфликт квот и одновременные заявки. Работает только с синтетическими данными в временной SQLite БД. Это **локальная** проверка отказоустойчивости; полноценное производственное нагрузочное и security-тестирование ещё предстоит.

### 5. TITAN-X26 — проверка CI отдельно от релизного согласования

В `.github/workflows/supreme-director-wave13-local-security.yml` создан самостоятельный `pull_request`/ручной workflow для Ubuntu Linux и Python 3.11/3.13. Он компилирует модули, запускает тесты, выполняет CLI chaos-проверку, проверяет JSON-доказательства, сохраняет артефакт и убеждается, что у оригинального плана нет подтверждённой production-приёмки.

**Релизная политика не ослаблена.** На ранее проверенном коммите `be92c116` браузерная проверка имела PASS, а оригинальный Python workflow завершился красным из-за защищённых исходных файлов PR (516 changed files, `ORIGINAL_SOURCE_MODIFICATION_REQUIRES_OWNER_REVIEW`). Этот запрет полностью сохранён и не может быть автоматически отменён локальным зелёным тестом.

## Важный CI дефект найден и исправлен

Первый Wave13 локальный CI `42527387125` выполнил 14 из 15 тестов успешно на Python 3.11 и 3.13. Единственный тест ошибочно ожидал отказ из subprocess при `2**63-1`, хотя более строгий TaskEnvelope отвергает такие значения ещё до запуска. Исправлено ожидание первого уровня защиты; сумматор дополнительно ограничен диапазоном точных JSON-целых (`2**53-1`) *включая результат сложения*. Новые CI запуски должны подтвердить итог.
