## X16 — Этапы brief → spec → code → review → release_candidate

Расширен существующий `campaign180/workflow.py`.

- `LocalProjectFlow.transition` добавляет явные `cancel` и `resume` в одной SQLite `BEGIN IMMEDIATE` транзакции.
- При отмене и возобновлении старый reviewer сбрасывается; новый кандидат требует отдельного нового code-review. Несанкционированное возобновление и устаревшие версии отклоняются.
- `candidate_manifest` собирает digest связанного brief, последней spec, кода, review, owner, reviewer и неизменяемой головы журнала событий. При нарушении цепочки, несоответствии reviewer или неподтверждённом коде вызывается fail-closed отказ.
- Кандидат всегда `release_candidate_only=true`, `production_release=false`. Декларация reviewer не заменяет независимую IdP-проверку.

## X17 — Генерация кода из проверяемой спецификации

В `campaign180/builder.py` добавлены `compile_verified_site` и
`verify_compiled_site`, не затрагивая существующий `render_site`.

- Точный expected SHA-256 канонической `SiteSpec` проверяется до генерации. Непроверенная или изменившаяся спецификация отвергается.
- Генерируется реально работающее содержимое нескольких статических HTML-страниц (HTML/CSS), в ZIP с фиксированными timestamp, modes, порядком и без сжатия. Результат воспроизводим побайтово.
- Канонический manifest сохраняет SHA-256 всех файлов, спецификации и входных данных; архив ограничен 1 MiB.
- Офлайн-верификатор проверяет внешний доверенный ZIP SHA, спецификацию, список путей, режимы/дату каждого файла и контрольные суммы. Повреждённые/чужие источники или опасные архивные пути отвергаются.
- Скрипты пользователя, внешние ресурсы, запуск кода и публикация отсутствуют.

## X18 — Независимая проверка патчей и policy gates

В существующем `campaign180/review.py` добавлены
`review_signing_message` и `verify_signed_patch_review`.

- `inspect_patch` повторно проверяет исходную базу каждого файла, пути внутри campaign180, Git-gate, отсутствие опасных функций, BIDI и секретов; только после успешного результата формируется подписываемое сообщение.
- Канонический документ связывает SHA-256 самого patch proposal и SHA-256 полного результата проверки с reviewer, отличным от автора.
- Ревьюер подписывает документ Ed25519; верификация выполняется без shell, с ограничением времени и точным DER SHA-256 публичного ключа, предоставленным из отдельной доверенной политики.
- Ошибка/изменение подписи, base SHA, содержимого или trusted key отказывается.
- В CI применяется временный TEST-ONLY ключ: он проверяет криптографию, но не является реальным удостоверением владельца. GitHub review/production merge и независимая проверка учётной записи не засчитываются.

## X19 — Автоматизированное исправление ошибок с лимитами

Усилен `campaign180/repair.py`.

- Автоматическое помещение повреждённых deterministic workflows в карантин остаётся ограниченным **3 за один вызов**; дополнительно введён общий проектный лимит **12 карантинных исправлений**. Бюджет фиксируется в digest предварительного плана.
- `inspect_replacement` проводит проверку предлагаемого исправления по реальной модели сайта и правам `workflow.manage`, строит хеш привязанный к quarantined SHA/revision.
- `apply_replacement` требует подтверждённый план, полномочия, реальную проверенную схему, актуальную revision и exact previous digest; транзакционно заменяет повреждённое правило и повторно включает его.
- Append-only `app_workflow_replacements` содержит предыдущий и новый SHA и время, предотвращая бесконтрольные подмены.
- Нет произвольных исправлений исходного кода, AI-генерации, доступа к сети и unattended публикующих действий. Неизвестную ошибку исправить автоматически без проверенной замены нельзя.

## X20 — Полноценный локальный no-AI редактор страниц

В `campaign180/structure.py` реализован `mutate_pages`, подключён через
`app_runtime.py` и POST `/api/v1/pages/manage` в `local_http.py`.
В `assets/index.html`, `console.js`, `console.css` создан интерфейс управления страницами в уже имеющейся панели.

- **Создание** страницы с безопасным slug, названием и текстовой секцией.
- **Копирование** страниц с их секциями.
- **Переименование адреса** с атомарным обновлением всех входящих CTA-ссылок.
- **Изменение порядка** страниц в навигации.
- **Удаление** с запретом удаления home и страниц, на которые ссылаются CTA.
- Все операции ограничены моделью `SiteSpec` (до восьми страниц), требуют `spec.write`, действующей tenant/project-сессии и exact revision. Запись выполняется в единой SQLite-транзакции; история хранится в неизменяемых `draft_revisions`. Сохранённое содержимое доступно в `render_site`/static preview.
- Локальный API требует bearer-токен, loopback host, защищён от неизвестных полей и постороннего tenant. Не является публичным SaaS API.

## Откат и ограничения

Изменения идут в Draft PR ветке, без merge. Для обратимого отката до
включения в продукт достаточно revert соответствующих коммитов X16–X20.
В новых SQLite таблицах X19 сохранена история immutable receipts, поэтому
удаление таблиц при rollback запрещено без сохранения и проверки данных.

**Не выполнены оригинальные требования independent acceptance:**
owner-approved KRAKEN/DevSwarm/Command source SHA отсутствует, реальный
отдельный identity reviewer не зарегистрирован, multi-source integration и
production deploy не тестировались. Результат — `BLOCKED_UPSTREAM`,
не `DONE`. Другие 175 оригинальных задач этим проходом не изменялись.
