## Блок 1. Устранение дублирования GitHub Actions

**Подтверждённый симптом:** у Wave 10 GitHub Actions runs для Python
и Chromium имеют статус `queued`; job runner не назначен. Это не
результат PASS и не результат FAIL.

**Исправлено в YAML:** обе проверки запускаются один раз через
`pull_request` плюс добровольный `workflow_dispatch`. Убрано
параллельное выполнение того же набора по `push` в ветку восстановления.
Введены отдельные `concurrency`-группы для Python и Chromium с
`cancel-in-progress: true`: новые проверки PR вытесняют устаревшие
запуски той же проверки.

**Дополнительный источник очереди:** исходный Draft PR содержит изменения
M187–M206, поэтому GitHub периодически запускает 17 исторических
workflow даже при очередном изменении `campaign180`. Для каждого
исторического workflow M187, M191–M206 добавлена собственная
`concurrency`-группа с отменой старых запусков того же события/PR.
Ни одна существующая проверка не удалена и ни один тест не отключён.
Изменения не распространяются на `main`, пока Draft PR не принят.

**Ограничение:** невозможно установить по одному статусу `queued`,
что именно задерживает предоставление runner (лимит, биллинг,
GitHub-инцидент, приоритет очереди и т. п.). Эта правка не является
доказательством устранения причины отсутствия runner. Запуски,
созданные до введения concurrency-группы, могут оставаться в очереди;
их необходимо отдельно проверить в GitHub Actions.

## Блок 2. Реальный изолированный restore drill

`campaign180/recovery_drill.py` создаёт согласованную SQLite-копию
исходной локальной базы с помощью SQLite Online Backup API и
`mode=ro`. Изоляция происходит во временном каталоге.

В этой копии механизм:
1. Проверяет права владельца, схему, записи и `builder_links`.
2. Создаёт канонический архив через `LocalProjectRecovery`, сверяет
   SHA-256 и все ссылки.
3. Восстанавливает архив только в **новый UUID проекта внутри копии**.
4. Сверяет записи с хешами, версии, отметки удаления, индекс связей,
   модели и страницы, принадлежность организации.
5. Сверяет неизменность исходных записей, связей, ролей и ревизии
   проекта внутри копии.
6. Подтверждает, что в восстановленном проекте только один владелец,
   нет делегированных прав, workflows или idempotency-ключей.
7. Удаляет временный каталог и возвращает только счётчики, хеш,
   технические ограничения и состояние PASS/FAIL.

Программа не меняет исходную базу, не подключается к внешним
серверам и не загружает архив в браузер. `source_database_modified=false`
означает отсутствие операций записи в исходную базу со стороны
этого скрипта. Доказательства долговременной надёжности, хранения
внешней резервной копии, восстановления после аварии и криптографического
происхождения архива требуют отдельной проверки.

## Блок 3. Консоль и разрешения

- `POST /api/v1/recovery/drill` — только localhost/127.0.0.1
  по авторизованному токену и роли `members.manage` (владелец).
- В разделе «Версии и откат» добавлена кнопка
  «Испытать восстановление на изолированной копии».
- По завершении отображаются только PASS, число сверенных записей
  и связей, укороченная SHA и подтверждение неизменности источника.
- Ни один endpoint не возвращает архив или клиентские записи.
- Ответ на некорректный токен и роль остаётся закрытым.

## Блок 4. Автоматические и отрицательные тесты

`tests/test_wave11_recovery_drill.py`:
- синтетические клиенты/заявки с реальной ссылкой;
- совпадение байтов SQLite-файла до/после локального испытания;
- сохранность данных и отсутствие нового проекта в оригинальной базе;
- отсутствие workflows/делегированных ролей в копии;
- отказ при испорченном хеше записи или разорванном индексе ссылок;
- запрет просмотра и запуска для viewer, другой организации или проекта;
- HTTP-аутентификация и отказ от неизвестных параметров;
- отсутствие пользовательских данных в API-ответе.

`browser-console.mjs` выполняет реальный клик и ожидает явного PASS,
после которого сверяет неизменность хеша текущего архива.

В Python CI добавлен шаг:
```bash
python -m campaign180.recovery_drill demo
```
Полный запуск из корня проекта:
```bash
export PYTHONPATH="$PWD/supreme-director/campaign180"
python -m unittest discover -s supreme-director/campaign180/tests -p 'test_*.py' -v
node --check supreme-director/campaign180/assets/console.js
node --check supreme-director/campaign180/tests/browser-console.mjs
```

Команды предназначены для локальной проверки или GitHub Runner.
**На момент публикации нет подтверждённого PASS Wave 11.**
Для подтверждения нужны точные успешные GitHub Actions runs.

## Внешние зависимости и статус исходного плана

Неподтверждены канонические upstream всех шести направлений,
свидетельство независимой приёмки, внешние backup/restore,
production IdP, TLS, операционный runbook инцидентов и допуск к
публикации. Локальное восстановление в SQLite не заменяет проверку
production PostgreSQL и фактический disaster recovery.

Оригинальные 180 ID **не повышены до независимо принятых**:
33 ID связаны с локальным кодом, 139 без прямых доказательств,
четыре вне scope и четыре без исходников. **0/180 принято.**
