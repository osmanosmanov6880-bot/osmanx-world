# OSGARD SUPREME DIRECTOR — Wave 8

Дата разработки: 6 ноября 2026. Только ветка `recovery/supreme-director-m187-20261104`, Draft PR #7. Сервер и production **не меняются**.

## Реальные блоки кода

**1. Form editor — TITAN-X20/X21.** `forms.py` и route
`PATCH /api/v1/pages/{slug}/form` позволяют менять заголовок, подпись кнопки,
модель данных, выбранные поля и порядок этих полей. Изменения только над
секциями `type: form`, с атомарной проверкой роли `spec.write` и точной
версией `expected_revision`. Каждая новая конфигурация создаёт
неизменяемую версию спецификации. Встроенная русская консоль содержит
чекбоксы полей и перемещение вверх/вниз. Форма в HTML-превью **не отправляет
данные**, кнопки и поля отключены. Публичного form POST пока нет.

**2. Reference choices — TITAN-X21/X22/X23.** Endpoint
`GET /api/v1/models/{model}/choices` возвращает не более 100
только **разрешённых записей текущего tenant/project** для селектора связи.
Он не выдаёт поля других организаций. `truncated=true` сообщает об
ограничении страницы. Клиентская форма использует `select`, не текстовое
поле UUID, и отменяет эффекты устаревших асинхронных запросов.
Проверка ссылок по-прежнему проходит транзакционно на сервере через
`builder_links`. Очищение необязательной ссылки записывает `null`;
очистить обязательную ссылку нельзя. Выборка ограничена 100 записями.

**3. Non-reference field rename — TITAN-X21/X24.**
`LocalModelEditor.rename_field` через
`POST /api/v1/schema/models/{model}/rename-field` переименовывает поле
в текущей модели без потери его значений, если нет несогласованных
workflow-зависимостей. При этом:

- За одну транзакцию обрабатывается максимум 500 строк включая tombstones.
- Каждая запись получает новую ревизию и новый хеш; хранимые JSON-ключи меняются.
- Списки выбранных полей в секциях формы обновляются в той же транзакции.
- Событие `RENAME_FIELD` сохраняется в append-only журнале миграций.
- Поля типа `reference` не переименовываются: им нужен отдельный план
  миграции ссылок. Поля из workflows также блокируются.
- При неправильной версии, повреждённой записи, чужом tenant или превышении
  лимита транзакция откатывается целиком.
- В консоли требуется явно отметить подтверждение изменения.

**4. Regression and real Chromium acceptance.**
`tests/test_wave8_forms_relations_rename.py` проверяет фактические
SQLite-связи, попытки доступа к другой организации/проекту, ограничения,
редактирование формы, миграцию и tombstones.
`tests/browser-console.mjs` расширен: визуальное редактирование формы,
создание связанной записи через селектор, переименование поля и повторное
статическое превью в Chrome. Итог прохождения проверять **отдельно** в
GitHub Actions — наличие теста не является его успешной приёмкой.

## Acceptance и блокеры

Это доказательства частичного **локального** кода по исходным ID, а не
оригинальная интеграция в KRAKEN / DevSwarm / Command, и не разрешение
публикации. Нет авторизованного реестра шести upstream и независимой
приёмки, нет production IdP и TLS, сетевой доступ закрыт, поэтому
**независимо принято 0/180**. CI для Wave 8 должен пройти отдельно.
