# M202 · Инженерный журнал / четыре крупные реализации

Дата: 5 ноября 2026. Репозиторий osmanosmanov6880-bot/osmanx-world, draft PR #7.

### A. Scheduler / локальная периодичность

Таблицы financial_monitor_schedule и financial_monitor_runs. Конфигурация интервала (1–168 часов), версий и сроков SLA; атомарная операция run_due. Пропущенные интервалы не дублируются, следующий назначается на now + interval. Одноразовый CLI через stdin с правами действующего owner. Никакого фонового демона и сетевых запросов.

### B. Risk history / последовательные снимки

Таблица financial_risk_snapshots, append-only SQLite триггеры, полный пересчёт и проверка цепочки SHA-256 при чтении, ограничение на размер. Чтение дельты метрик между двумя сохранёнными снимками без придумывания финансовых значений; без самостоятельной доверенной подписи и внешнего якоря.

### C. SLA / качество реакции

Таблицы financial_sla_episodes, financial_sla_state и financial_sla_events. Три вида эскалации: нет подтверждения риска, риск не разрешён по SLA, просрочена задача M195. Только ручной refresh или явно вызванный run_due; повторный вызов не дублирует сигнал. После нормализации статус переводится в cleared; роль owner обязательна. Мобильные пуши, email и WhatsApp не отправляются.

### D. Executive Center / интерфейс + отчёт

Серверная операция commerce.monitor.report собирает срез локальных метрик и статусов без новых финансовых проводок. Экспорт CSV с ограничением размера и formula-injection guard. Русская адаптивная панель /watch/ с настоящими данными из SQLite. Токен доступа только в памяти браузера, loopback-only и same-origin CSP.

### Проверка

Автоматизированные unit/HTTP tests M202, offline smoke со связкой M201 scan → snapshots → SLA → M195 task → report, регрессии M192–M201 и JavaScript syntax в GitHub Actions на Python 3.11/3.13. Визуальную физическую браузерную приёмку не заявлять.

### Production gate

Production NO-GO. Независимая приёмка исходных 180 upstream-задач 0/180. Локальная целостность != независимая доверенная аудиторская подпись. Реальные денежные перечисления и банковская верификация отсутствуют.

### Откат

Перед миграцией: остановить старый процесс, проверить резервную копию SQLite включая WAL. При проблеме остановить M202 и восстановить предыдущую БД в новый файл, использовать предыдущий зафиксированный код. Не удалять таблицы M202 вручную.
