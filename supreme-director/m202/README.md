# OSGARD SUPREME DIRECTOR — M202 / Центр мониторинга

**Четыре полноценные подсистемы поверх M201:** локальное расписание, история изменений рисков, контроль SLA ответственных и управленческий отчёт с CSV. Исходный код работает поверх M192–M201 и существующей SQLite, без отдельной финансовой базы.

## Блок 1: локальное расписание проверок

Операции:
- commerce.monitor.schedule.get / schedule.set — версия конфигурации, интервал 1–168 часов, срок подтверждения и решения риска, состояние включено/выключено.
- commerce.monitor.schedule.run_due — атомарная проверка **только если наступил срок**. При опоздании запускается один раз, а не сотни раз «задним числом».
- commerce.monitor.runs.list — история фактически выполненных проверок.

**Внутри приложения НЕТ постоянно работающего планировщика.** Периодическое исполнение требует, чтобы администратор подключил одноразовую CLI-команду к локальному Task Scheduler или cron. Важно отличать _расписание, сохранённое в базе_, от реально установленной задачи ОС.

Для однократной проверки по расписанию, с безопасной передачей токена по stdin:

    cat /restricted/owner-token.txt | python3 -m osgard_m202 run-due --db ./local.sqlite --token-stdin

Файл с токеном должен быть доступен только владельцу процесса (например chmod 600); не выводите токен в лог, shell history, URL или аргументы командной строки. Этот пример не создаёт cron автоматически.

## Блок 2: история и сравнение

Операции:
- commerce.monitor.scan — ручное сканирование M201 плюс снимок риск-метрик.
- commerce.monitor.snapshots.list — снимки финансовых рисков с SHA-256 цепочкой, проверкой целостности и явной маркировкой отсутствия внешнего якоря.
- commerce.monitor.snapshots.compare — реальные изменения пяти правил между выбранными снимками.

Фактические расходы и поступления читаются из локальной SQLite, новые числа не создаются. Данные клиентских документов не копируются в историю рисков.

## Блок 3: контроль SLA ответственных

Операции:
- commerce.monitor.sla.refresh — явная проверка просроченного подтверждения риска, превышения срока решения, а также просроченной задачи M195.
- commerce.monitor.sla.board — текущие и зафиксированные нарушения, этапы эскалации и ответственные.

Записи в immutable журнале защищены локальной hash-chain; повторное исполнение не создаёт дублей. Устранение проблемы или завершение задачи снимает активный SLA-сигнал при следующей проверке.

**Нет** автоматических внешних уведомлений, email, WhatsApp, Push или изменения заданий сотрудников без их явного действия.

## Блок 4: русская панель и отчёт руководителя

Локальный адрес: http://127.0.0.1:8722/watch/

- Конфигурация расписания, проверка срока и ручное сканирование.
- История сравнений, открытые SLA-нарушения, отчёт владельцу.
- commerce.monitor.report — свежие показатели текущей базы и сохранённые инциденты.
- commerce.monitor.report.csv — CSV UTF-8 с BOM и защитой от инъекций формул.

**Только tenant owner** видит отчёты, политики и суммы; операторы продолжают работать со своими задачами M195/M201 без доступа к этому центру. Token хранится только в памяти вкладки.

### Запуск на новой базе

Из корня репозитория. Python 3.11+, SQLite:

    export PYTHONPATH="$(pwd)/supreme-director/m192:$(pwd)/supreme-director/m193:$(pwd)/supreme-director/m194:$(pwd)/supreme-director/m195:$(pwd)/supreme-director/m196:$(pwd)/supreme-director/m197:$(pwd)/supreme-director/m198:$(pwd)/supreme-director/m199:$(pwd)/supreme-director/m200:$(pwd)/supreme-director/m201:$(pwd)/supreme-director/m202"
    python3 -m osgard_m202 init --db ./local.sqlite --tenant "Моя компания"
    python3 -m osgard_m202 serve --db ./local.sqlite --port 8722

На Windows в PYTHONPATH используйте точку с запятой между каталогами.

**Для существующей базы M201 не используйте init.** Остановите прежний процесс, создайте проверенный резервный снимок SQLite с учётом WAL и запустите новую версию командой serve. Схема M202 только добавляет таблицы.

## Границы и выпуск

- Начальный баланс и ожидаемые поступления могут быть ручными гипотетическими значениями, это не банковская выписка.
- Локальные SHA-256 цепочки **не имеют независимой доверенной подписи**.
- Нет фонового выполнения внутри приложения и никаких внешних контактов.
- Производственный деплой и merge в main не разрешены. Исходные 180 инженерных задач **0/180 независимо приняты**. Production NO-GO. Реальная мобильная визуальная приёмка должна проводиться отдельно.
