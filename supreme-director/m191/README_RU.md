# OSGARD SUPREME DIRECTOR — M191: восстановление журнала

M191 — самостоятельный **локальный механизм резервного копирования, проверки и восстановления** журнала M190. Это продолжение инженерной реконструкции, а не доказательство реального выполнения 180 задач, не авторизация production и не сервис удалённой синхронизации.

## Условия безопасности

- Используйте только проверенный журнал M190 и сохранённый **вне базы и вне каталога резервной копии** контрольный хеш (external anchor) M190. При подмене одновременно базы и её якоря невозможно установить достоверность исходного состояния без отдельного доверенного хранилища.
- На входе и выходе проходит полная проверка цепочки хешей M190 и SQLite `PRAGMA integrity_check`.
- Копирование активной SQLite с WAL — через штатное `sqlite3.Connection.backup`, не сырой `cp`.
- Публикация каталога резервной копии осуществляется через staging и атомарное переименование. В случае прерывания staging удаляется.
- Восстановление — только в **НОВЫЙ** файл базы. Существующие файлы не перезаписываются.
- Манифест содержит SHA-256 байтов SQLite и внешнего якоря, хеш цепочки, число событий, SHA-256 плана, постоянный `NO_GO` и `production_authorized=false`.
- Не вводите секреты/ключи в заметки. Этот модуль не отправляет данные по сети и не изменяет GitHub.

## Команды

Из корня репозитория (Python 3.13, без сторонних библиотек для M191):

```bash
# Получите/храните проверенный якорь отдельно от backup.
PYTHONPATH=supreme-director python3 -m m191 backup \
  --db /data/m190.sqlite \
  --anchor /trusted/m190-head.json \
  --bundle /offline-backups/m191-20261104

PYTHONPATH=supreme-director python3 -m m191 verify \
  --bundle /offline-backups/m191-20261104 \
  --anchor /trusted/m190-head.json

PYTHONPATH=supreme-director python3 -m m191 restore \
  --bundle /offline-backups/m191-20261104 \
  --anchor /trusted/m190-head.json \
  --out-db /recovery/new-m190.sqlite
```

Подставьте свои реальные **локальные** пути и запускайте команды только на изолированном диске. В примере они не существуют и ничего автоматически не запускают. Не используйте на production без отдельной процедуры.

## Тесты и воспроизведение

```bash
PYTHONPATH=supreme-director python3 -m unittest discover -s supreme-director/m191/tests -p 'test_*.py' -v
PYTHONPATH=supreme-director python3 supreme-director/m191/smoke.py
PYTHONPATH=supreme-director python3 supreme-director/m191/verify_source.py
```

Сценарии проверяют копирование после WAL, реконструкцию 180 блокировок из M189, добавление заметок, внешний якорь, намеренно изменённые файлы, отказоустойчивость и запрет перезаписи. Все тестовые данные синтетические.

## Ограничения и выход в production

Нельзя называть положительный результат `PASS_LOCAL_ONLY` успешным восстановлением шести продуктовых upstream. Оригинальные M180/M181 пока не восстановлены, 0/6 owner-approved upstream; 0/180 независимо принятых пакетов, release `NO_GO`. Без внешнего неизменяемого якоря SHA-цепочка не защищает от злонамеренной переписи всей истории. Дублирование резервных копий в одном каталоге не заменяет изолированное хранение.
