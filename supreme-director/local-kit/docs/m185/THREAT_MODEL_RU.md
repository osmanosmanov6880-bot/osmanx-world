# M185 — дополняющий threat model и пределы проверки

- **Основная граница:** пользовательские записи и локальные review cases. Защита по SHA-256 и Ed25519 — не аналог внешнего attestation сервиса и не гарантирует реальную независимость человека.
- **Ключи:** в приложении хранится только публичная часть доверенного реестра. Регистрация публичных ключей разрешена только офлайн-оператору с ожидаемым SHA предыдущего пустого реестра. Закрытые ключи никогда не вводятся в браузер и не входят в ZIP.
- **Саморевью:** сравнение идентификаторов proposer/reviewer без учёта регистра плюс проверка от доверенного публичного ключа. Идентификатор автора по-прежнему локально самообъявленный — настоящая SSO identity отсутствует.
- **Подмена файлов:** case привязан к `evidence.id` и SHA; перед challenge, submit и doctor байты проверяются заново. Registered evidence UPDATE/DELETE и review UPDATE/DELETE блокируются SQL-триггерами, но локальный администратор БД может их удалить. Полного tamper resistance здесь нет.
- **Повторное голосование:** case допускает одну подпись; изменить decision/reviewer/verdict/reason без новой записи запрещено. Отвергается подписанная заявка на иной case или с другой причиной.
- **Атаки по API:** сохраняются M184 origin/Host/token/CSP, body size cap, отказ неизвестным route, SQL-параметры, binding 127.0.0.1. Не проходил внешний pentest, не годится для интернет-хостинга.
- **Пределы доверия:** исходники M181, six canonical upstream, настоящий файл конфликтов, девять API схем и независимые production подписи не доступны. Ни один локальный review не вправе менять оригинальные 180 task IDs на ACCEPTED.
- **Хранение:** локальная SQLite не шифруется, reviewer keys находятся у внешних людей, свидетельства надо хранить без PII и паролей. Внешний KMS/HSM и аудит вне хоста отсутствуют.
- **QA:** Chromium emulation plus Python-to-HTTP loopback bridge — это не доказательство поведения на реальном железе или через общедоступный HTTPS.

**Остаточный риск: HIGH для публичной сети. Сетевой production release: NO-GO.**
