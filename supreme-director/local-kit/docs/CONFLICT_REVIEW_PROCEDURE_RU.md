# Проверка 28 конфликтов M181 — процедура независимого решения

Этот файл не утверждает, что оригинальные пути 28 конфликтов восстановлены.

## P0 (17 карточек)

Каждая карточка должна иметь пару `path@sha256` из оригинальных ZIP, canonical upstream base SHA, дифф, threat model, тесты и независимое мнение CODEOWNER+security. При конфликте IAM, RBAC, secret, signing, payment, sandbox, task/lease, data migration, API auth или provenance release всегда действует запрет на автослияние.

## P1 (11 карточек)

Процедура такая же, допускается иной порядок очереди. Переход в P1 не является отказом от security review. Для конфликтов UI/locale нужно предъявить реальные screenshots/touch/keyboard tests, для медиа — лицензию и целостность asset, для исследовательских данных — исходный dataset и воспроизводимость.

## Обязательная последовательность

1. SHA-pinned read-only ZIP inventory каждого входного релиза (не «похожие» имена).
2. Два оригинальных digest и exact base SHA; сохранение исходных bytes.
3. Ручной выбор KEEP_LEFT / KEEP_RIGHT / MANUAL_MERGE с объяснением семантики.
4. Negative tests для изменённой функциональности; контрактные тесты для её consumers.
5. PR только в branch владельца продукта, отдельный независимый reviewer и CI на *итоговом head*.
6. Отметка `REVIEW_CANDIDATE`, затем внешняя machine/human verification. Не применять `ACCEPTED` из авторского JSON.
7. Переиспытание связанного contract (из 9) на фактическом интеграционном commit.
8. Принятие parent task только после подтверждения исходного оригинального ID/294 графа.

## Чего не делать

- Не подставлять в 28 карточек произвольные имена файлов или те, что «похожи» в другом репозитории.
- Не удалять 18 cache файлов/SQLite или не включать их по умолчанию в release; принимать только разрешённые исходники.
- Не встраивать два шрифта STYLO в public bundle без лицензии и provenance.
- Не считать статус GitHub CI без проверки его exact head SHA, критических jobs и независимого review.
