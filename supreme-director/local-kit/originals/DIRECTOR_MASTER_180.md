## Главная инженерная директива

Продолжайте от последнего зафиксированного состояния, **не создавайте очередной несвязанный прототип вместо интеграции**. Вначале установите канонические repo URL, branch, immutable Git SHA, lockfiles и реальную схему продукта. Каждый пакет дробите на исполнимые подзадачи в локальном TASK_BOARD. Выполняйте независимые разрешённые этапы последовательно, не останавливаясь ради ненужного подтверждения каждого шага, пока хватает инструментов, контекста и доступа; **невозможно продолжать работу после завершения сессии без отдельной среды исполнения / автоматизации**. При настоящем блокере фиксируйте доказательство, пропускайте только заблокированную часть, продолжайте следующие независимые задачи.

**Запрещено:** production deploy без полномочий, реальные внешние отправки, реальные платежи, публичный выпуск токенов, управление спутниковым оборудованием, чтение/публикация секретов, правки чужого домена, обход аудита, фальсификация тестов. Все внешние действия требуют владельца и уникального operation ID. Генерируемые решения ИИ не являются разрешением на исполнение.

### Универсальная приёмка каждого пакета
1. Запишите ID, исходный Git SHA или `UNKNOWN/BLOCKED`, целевую ветку, объём и точные изменённые пути.
2. Сделайте код/схему/миграции/UX изменения и Git diff. При отсутствии checkout сделайте строго обозначенный самостоятельный прототип, не выдавая его за продуктовую интеграцию.
3. Тестируйте unit, integration, negative/security, regression и E2E **по применимости**; сохраняйте команды, exit codes и сырые журналы.
4. Проверьте несовместимость API, RLS/RBAC, tenant isolation, секреты и восстановление; отдельные исключения документируйте.
5. Приложите PR/commit/архив с SHA256 и rollback/restore план. Заявление `PASS` только для действительно запущенных проверок.
6. Передайте независимому SUPREME DIRECTOR. До принятия итог: `PLANNED`, `IN_PROGRESS`, `BLOCKED` или `READY_FOR_REVIEW`, **не `VERIFIED`**.

### Волны и зависимости
- **Wave 0 (P0):** baseline, зависимости, доступ к исходникам, ownership, угрозы; без этого нельзя мерджить продуктовые изменения.
- **Wave 1 (P0):** identity, schema, auth, sandbox и тестовый контур, проверка восстановления.
- **Wave 2 (P1):** интеграция реальных модулей через версионированные контракты.
- **Wave 3 (P1):** реальные E2E и производительность на целевых системах.
- **Wave 4 (P2):** расширения, исследования, решение независимого релизного аудитора.
