# M198 · Инженерный журнал финансового модуля

Дата: 2026-11-05. Ветка восстановления: `recovery/supreme-director-m187-20261104`, PR #7.

## Объём

Добавлены три таблицы `delivery_finance_budgets`, `delivery_finance_expenses` и `delivery_finance_receivables` без удаления прошлых таблиц. Классификация операций производится по доверенному токену и проекту, не по `tenant_id` из входного JSON. Все финансовые записи изменяются в `BEGIN IMMEDIATE` транзакции SQLite с контрольным ключом повторения.

Реализованы API: `commerce.finance.snapshot`, `commerce.finance.history`, `commerce.finance.budget.set`, `commerce.finance.expenses.add`, `commerce.finance.expenses.commit`, `commerce.finance.expenses.void`, `commerce.finance.receivables.add`, `commerce.finance.receivables.resolve`.

В русской панели `/finance/` доступны бюджет, прогноз, факт, ожидаемые оплаты, изменение статуса расходов, ручные поступления и журнал. Для завершения оплаты нужен документ **текущей версии того же проекта**; проверяется SHA-256 именно реальных байтов документа.

## Формулы и ограничения

- Все суммы представлены в копейках (`amount_minor`) целым числом, лимит одиночной записи 1e12 копеек.
- Факт = сумма активных расходов `incurred`.
- План = сумма активных расходов `planned`.
- Прогноз = факт + план.
- Отклонение = прогноз − бюджет. Без установленного бюджета отклонение равно `null`, а не вымышленному нулю.
- Ожидаемые оплаты = все ручные записи, кроме отменённых.
- Ожидаемая маржа = ожидаемые оплаты − прогноз. Это бизнес-гипотеза, не подтверждённая бухгалтерская прибыль.
- Признак `external_bank_verified` всегда `false`; `real_payment_executed` всегда `false`.

## Тесты

Новый модуль имеет 37 unit / HTTP / negative тестов (локальный прогон PASS). Полная регрессия M192–M198: **320/320 PASS** (Python локально). Браузерная визуальная приёмка в настоящем Chromium здесь не подтверждена; проверены HTTP-ресурсы, авторизация, CSP и синтаксис JavaScript.

## Риски

1. Не реализован банковский эквайринг и банковская сверка. Статусы оплат отражают ручные заметки.
2. Локальный JSON не подписан доверенным клиентом/банком, а SHA-256 не защищает от администратора, который заменит базу и внешний якорь одновременно.
3. Долгосрочные финансовые оценки не включают налоги, НДС, зарплатные начисления, валютные курсы и бухгалтерские проводки.
4. Нельзя выдавать модуль M198 за выполнение всех 180 исходных задач. Нет product-wide E2E и независимой приёмки.

## Безопасный откат

Перед запуском на существующей M197 БД создать проверенный SQLite backup. Старые таблицы не изменяются, но не следует запускать старую версию приложения на активно меняющейся базе. Для отката остановить M198 и восстановить резервную копию в новый файл, затем запустить прежний проверенный commit. Не удалять таблицы вручную.
