# R8 — расходы, выгрузки и журнал личного штаба

API остаётся под `/moscow-1000/api/command`. Все новые маршруты требуют действующую серверную Google/Cloudflare Access сессию и роль сотрудника. Публичный `/public` сохраняет прежнюю границу: только явно опубликованные агрегаты.

## Миграция

После `0006_r7_command_requests.sql` примените `0007_r8_command_ledger.sql`. Она добавляет к `command_expenses`:

- `revision INTEGER NOT NULL DEFAULT 1 CHECK(revision > 0)`;
- nullable `updated_at TEXT` и `updated_by TEXT`;
- индекс категории/дня, а к `operator_audit` — индекс события/времени.

Миграция не вставляет демонстрационные записи и не изменяет старые суммы/даты. Для старой строки API возвращает `updatedAt = created_at` до первого редактирования. Отсутствующая миграция блокирует операции с расходами и выгрузки с `503 migration_required`.

В отдельном Site схема разворачивается без строк данных, а `command_state` появляется при первой авторизованной записи. До этого расходы, бюджет и выгрузка корректно возвращают ревизию `0` и пустые наборы. Само чтение не создаёт деловые записи; явная выгрузка добавляет только своё событие аудита.

## Расходы и бюджет

`GET /expenses?day=1&category=food&offset=0`

`day` и `category` необязательны; категория сравнивается буквально, допускает существующие пользовательские категории. Ответ содержит `expenses` (до 25 строк), `nextOffset`, `total` (все подходящие строки), `totalKopecks`, `totalRub`, `revision` всего штаба. Пагинация и общая сумма читаются одной транзакцией. Сумма не меняется от количества страниц, загруженных в интерфейсе.

Expense DTO: `id`, `revision`, `day`, `amountRub`, `amountKopecks`, `category`, `note`, `createdAt`, `updatedAt`.

`GET /expenses/:id` возвращает `{ok:true,expense}` либо `404`. Доступен сотрудникам с правом чтения.

`PATCH /expenses/:id` требует роль редактора, совпадающий Origin, JSON и полный набор редактируемых полей:

```json
{"day":2,"amountRub":120.45,"category":"transport","note":"Комментарий","expectedRevision":1}
```

Сумма хранится целым числом копеек. Дробные копейки, нулевые/отрицательные суммы и неизвестные поля отклоняются. Запись, её ревизия, ревизия штаба и аудит меняются атомарно. Старая ревизия возвращает `409` без побочных записей. Ответ содержит версию именно этой транзакции. Если другой сотрудник изменит строку сразу после неё, первый ответ не будет ошибочно описывать чужую версию.

`DELETE /expenses/:id` принимает `{expectedRevision}` и защищает удаление той же проверкой. Для совместимости с R6/R7 сохранён прежний явный запрос `{}` без проверки версии. Новый интерфейс всегда передаёт ревизию. Повтор старого идемпотентного POST после удаления по-прежнему возвращает `410` и не восстанавливает строку.

`GET /budget` возвращает полную сводку за экспедицию:

- `revision`, `limitKopecks = 10000000`, `limitRub = 100000`;
- `totalKopecks`, `totalRub`, `totalCount`, `remainingKopecks`, `remainingRub`;
- `days`: все десять дней с `day/count/totalKopecks/totalRub`, включая нули;
- `categories`: все фактические категории с количеством и суммой.

Отрицательный остаток показывает превышение планового лимита; сервер не маскирует его нулём. Сводка получается одним согласованным чтением.

## Выгрузка владельца

Только редактор может явно скачать `GET /export?format=json`, `contacts.csv` или `expenses.csv`. Кросс-доменные Origin/Sec-Fetch-Site отклоняются. Ответы содержат `Cache-Control: no-store`, `X-Content-Type-Options: nosniff` и `Content-Disposition: attachment`.

JSON включает `schemaVersion`, название проекта, `exportedAt`, ревизию штаба, количество строк, все контакты, все расходы, сохранённые состояния квестов (включая невыполненные) и опубликованную сводку с её версией/исходной ревизией. Все эти данные читаются в одной транзакции. Изменения после чтения не смешиваются с выгрузкой. Сводка проходит проверку и реконструируется по разрешённым полям.

В выгрузку не входят Google-сессии, OAuth-потоки, ключи, переменные окружения, идемпотентные квитанции, другие таблицы рассылок/обращений и полный операторский аудит. Это переносимая выгрузка операционных данных; автоматический импорт в R8 не предоставляется и не подразумевается.

CSV имеет BOM UTF-8, CRLF между строками, кавычки вокруг всех ячеек и удвоение встроенных кавычек. Переносы строк внутри поля сохраняются. Формулоподобные строковые значения, включая префиксы из пробелов/табуляций/переносов и `= + - @`, превращаются в буквальный текст с апострофом. Числовые значения остаются числами. CSV расходов содержит и рубли, и точные копейки.

Заголовки ответа:

- `X-Export-Revision` — ревизия выгруженного снимка;
- `X-Export-Count` — количество строк выбранного CSV либо сумма контактов/расходов/квестов JSON;
- `X-Export-Contacts`, `X-Export-Expenses`, `X-Export-Quests` — количества во всей базе на момент снимка;
- `Content-Digest: sha-256=:BASE64:` и `X-Content-SHA256` — SHA-256 фактических байтов файла, включая BOM и переводы строк.

Защитные пределы: 10 000 строк каждой выбранной таблицы и 8 MiB итогового файла. При превышении возвращается `413 export_too_large`, файл не выдаётся, данные не обрезаются. Отдельный CSV небольшой таблицы доступен, даже если другая таблица превышает предел. Более крупную базу нужно экспортировать штатными средствами D1 владельца. Невалидная опубликованная сводка блокирует полный JSON (`503 invalid_publication`), отдельные CSV остаются доступны.

Успешно подготовленная выдача фиксируется событием `command_data_exported`, без изменения деловой ревизии. Если аудит не записался, файл не выдаётся (`503 export_audit_unavailable`). Событие означает подготовку ответа сервером; сервер не может доказать, что браузер записал файл на диск. Повторное явное скачивание создаёт отдельное событие.

## Журнал действий

`GET /audit?category=all&cursor=...`

Категории: `all`, `contact`, `expense`, `quest`, `publication`, `export`. Ответ: `events`, `total`, `nextCursor`. Каждое событие содержит `id`, фиксированное имя `event`, адрес сотрудника `actor`, безопасный идентификатор `subjectId` или `null`, время `at`.

Отдаются только известные события командного штаба, без событий других подсистем, полей контактов или заметок. Курсор привязан к категории; сортировка `(at DESC,id DESC)` сохраняет события с одинаковым временем. Верхняя граница вставок фиксируется на первой странице, поэтому новые события не сдвигают продолжение истории. Курсор не является токеном доступа и не даёт никаких прав без сессии. Смена фильтра требует нового чтения без старого курсора.

## Проверки

```sh
node --test tests/moscow-1000-r8-backend.test.mjs
node --test tests/moscow-1000-*.test.mjs
```

Тесты используют свежую SQLite с настоящими миграциями, конкурентные барьеры, ошибки аудита с откатом транзакции, многостраничные наборы, новые вставки между страницами, крупные выгрузки, точность копеек и анонимный вход через настоящий Worker. Тестовые данные существуют только в памяти тестов, не в рабочей миграции или опубликованной базе.
